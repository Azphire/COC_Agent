## 实现

- 新增 `improvise` 回应类别，旧 `unrecorded` 进入同一流程。删除必须回答“不知道／记不准”的提示及字面拦截；保留 NPC 人物描述，要求先回答当前问题，再适度给出可探索方向，由玩家决定做法。普通留白无需主机审阅；核心事实变更、隐藏信息、检定、资源、玩家决定仍受原机制约束。
- KP 可以补充普通见闻、环境、可读文字及临时互动对象。`incidental_details` 进入实际生成语法，每轮最多两条、每条最多 160 字符；这些文字不会创建线索实体、出口或资源。
- 发布阶段只保存最终旁白或 NPC 台词中原样出现的短句，分别归入 `keeper.narration` 和 `npc.spoke`。事件保留说话人、`scene_id`、`incidental_source=kp_improvisation`。未说出的草稿被排除；被拒绝输出和回退内容不产生即兴记录。公开校验同时检查该字段中的私密内容。
- 后续 KP、队友与公开回应按当前问题检索事件记录。沿用 `story_v1` 的有效读档分支，在近期对话和摘要裁剪之前选取；按问题文字相关性、场景和事件新近程度排序，最多六条、约 1400 字符预算，标注当前场景或历史位置。检索为有界字词匹配，不是完整语义检索。
- 摘要输入保留即兴出处，服务端为摘要附上最多六条相关来源记录的说话人、场景、事件序号及原话，明确不是关键发现。更早的原始记录仍可从事件档案独立检索。
- 即使规划没有选中公开事实，公开回应也能取得当前场景候选。模型回退文本提供已有公开内容和可继续尝试的方向，删除通用“无法完成这项行动”结束语。
- 仅对明确标记为只读且参数模型为空的工具归一化参数为 `{}`，规划校验及工具执行均采用这一规则。有参数工具和修改状态的工具保持原参数校验。对应的旧测试断言按新要求更新。

主要变更在 `backend/app/agents/` 和 `backend/app/memory/`。线索面板、前端源码、依赖声明、原始模组、规则资料、原 `.env` 和用户库未修改；没有 commit 或 push。
