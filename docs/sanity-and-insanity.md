# SAN 检定、疯狂状态与恢复

## 核对的规则

来源为本地《克苏鲁的呼唤第七版规则书1907.pdf》，SHA-256 `bc8455d443ec4c64ae86ec2d6e6637889eff2cd59a4cc4686076e95b130d08dc`。以下 PDF 页码从 1 开始；印刷书页比 PDF 页码少 1。不套用普通技能的困难／极难成功等级。

| 内容 | 核对页码 | 本批行为与裁定边界 |
| --- | --- | --- |
| SAN 判定、成败损失 | PDF 130–131／书页 129–130，§8.1 | 百分骰不超过当前 SAN 则成功；分别使用批准效果的成功／失败损失。无奖惩骰、幸运抵扣或孤注一掷。 |
| 极端骰点 | PDF 77／书页 76，§5.5；PDF 131／书页 130 | SAN < 50 时 96–100 大失败，SAN ≥ 50 时仅 100；损失取失败公式最大值。01 按 SAN 二元比较成功；本地 SAN 段未规定成功损失骰自动取最小值，因此仍执行批准成功公式。SAN 为 0 不再发起检定。 |
| 单次创伤与 INT | PDF 132／书页 131，§8.2 | 单次实际损失 ≥ 5、尚未直接触发不定性／永久性疯狂且当前清醒时，等待普通 INT 检定；成功触发临时性疯狂，失败不触发。 |
| 一天累计 | PDF 132／书页 131 | 同一游戏日累计损失达到日初 SAN 的 1/5，直接不定性疯狂。按整数交叉乘法比较，不提前向下取整阈值。游戏“一天”由主机按充分休息等情节明确划分；不是自然日或滚动 24 小时。 |
| 类型与阶段、归零 | PDF 131–133／书页 130–132 | 保存临时性／不定性／永久性疯狂；发作和潜在疯狂分别记录。SAN 归零永久性疯狂，不能继续自主调查，也不支持治疗解除。 |
| 症状和时长 | PDF 133–135／书页 132–134，§8.3 表 VII／VIII | 主机选择具体症状并确认掷持续骰：即时发作 1d10 轮、总结发作 1d10 小时；临时疯狂另有 1d10 小时。使用主机推进的游戏分钟／轮。当前实现从触发时起计算临时疯狂总时长，包含发作时间；书中容许是否计入发作时间的裁定，本批固定选择计入。 |
| 发作保护和复发 | PDF 132、135、139／书页 131、134、138 | 发作及待主机确认症状期间免疫进一步 SAN 损失；该遭遇记零损失回执，不掷额外 SAN。潜在疯狂期间任何正损失重新发作，原临时疯狂截止时间不刷新。 |
| SAN 上限、神话导致疯狂 | PDF 131、139／书页 130、138 | 上限 99 − 快照中的克苏鲁神话 − 运行时神话增量。批准效果明确标记 `mythos=true` 时，首次进入神话导致的临时性／不定性疯狂增加 5，后续再次进入或升级类型增加 1；潜在疯狂的同类型复发不重复增加。现行神话技能检定叠加该增量，原快照不变。上限收缩另有状态记录，不当作新的遭遇骰。 |
| 解除与治疗 | PDF 140–141／书页 139–140，§8.4 | 主机按到时或安全场所良好睡眠确认临时疯狂恢复。不定性疯狂只接受有说明的主机治疗结果或章节结束裁定；跨日和时间推进本身不治疗。月度护理／收容所的整套治疗骰流程未自动化，由主机记录已核实的检定和治疗依据。 |

失败的瞬间失控由批准效果的 `involuntary_action` 提供，默认“惊恐地呆立一瞬”；这是可编辑的主机选择。症状支持主机直接选择，未自动随机选择表 VII／VIII；发作持续时间仍由服务器掷骰。总结症状可能伴随 HP、物品、位置或人物关系变化，这些由主机处理，不自动启动伤害、装备或战斗系统。恐惧／躁狂的具体诱因须主机填写。重复接触同类神话存在的“习惯恐惧”、现实认知、阅读、法术及恢复 SAN 奖励不在本批自动结算范围。

## 准备与使用

在实体草稿的“编辑检定与公开条件”中设置 `sanity_effects`，保存后重新批准；房间沿用已有准备版本冻结机制。每项绑定该批准实体，并明确遭遇名称、触发事件和来源。

```json
{
  "id": "corpse-san",
  "encounter": "目睹血肉模糊的恐怖尸体",
  "trigger": "action_target",
  "success_loss": "1",
  "failure_loss": "1d4+1",
  "source": "coc7-1907:bc8455d443ec4c64ae86ec2d6e6637889eff2cd59a4cc4686076e95b130d08dc",
  "page": 131,
  "basis": "§8.1 理智损失范例",
  "visibility": "actor_and_host",
  "mythos": false,
  "involuntary_action": "惊恐地呆立一瞬"
}
```

`trigger=action_target` 要求实际 `action.submitted` 的行动者和 `target_entity_id` 匹配；`entity_revealed` 要求真实 `entity.revealed` 的实体匹配。KP 还须使用本轮事件、当前场景实体；回顾和规则问题不构成新的 SAN 遭遇。未批准配置不得请求扣点。同一角色、同一实体遭遇事件只能选择一个效果，不能换效果重复扣减。不同的实际遭遇是否应再检定，由主机／批准配置决定。

模组依据使用 `source="module:<该准备的 source_hash>"`，`page` 必须在实体 `source_pages` 中。规则依据仅接受上述精确版本和本批核对页。来源与公式的校验不代替主机对文字内容的审阅。允许 `0`–`100` 常数或小写 `NdM±K`，至多 10 颗、每颗 2–100 面，公式所有可能结果必须落在 0–100；禁止任意代码、负结果和无限骰式。

主机／本人在理智面板读取现值、上限、累计和历史。KP 的有界上下文优先注入行动者当前运行时，其他角色可通过已有权限的 inspect 工具读取；AI 队友只读自己的运行时。公开叙事仅接收 `visibility=public` 的已确认结算。规则问答仍只检索／解释规则，不发起检定、扣减或改变累计。

## 接口与事务

均使用既有房间认证、锁、事务和广播。

| 接口 | 权限及参数 |
| --- | --- |
| `POST /api/rooms/{room}/sanity/encounters` | 主机；`target_member_id, entity_id, effect_id, source_event_seq`。无活动回合时补发已批准遭遇。 |
| KP 工具 `request_sanity_check` | 同上四个参数，不接受点数或公式；使用现有回合／工具回执。 |
| `POST /api/rooms/{room}/sanity/checks/{id}/roll` | 真人本人或主机；`expected_stage=san/loss/int/duration`。AI 由服务端串行执行。旧阶段重试不会误掷下一阶段。 |
| `POST /api/rooms/{room}/sanity/manage` | 主机；`expected_revision, operation, reason`，按操作填写 `slot_id, minute, round, symptom, mode, recovery_basis`。 |
| `POST /api/rooms/{room}/resources/correct` | 主机；`expected_revision, slot_id, resource, value, reason`。专用资源更正，不发布 `scene.updated`，不计入遭遇累计。 |

`operation` 为 `advance/new_day/symptom/end_bout/recover`。时间只能向前；解除发作必须到达记录的分钟／轮。`recover` 的 `recovery_basis` 为 `elapsed/safe_sleep/host_treatment/chapter_end`，后两项用于不定性疯狂。时间推进和恢复是两次明确操作。一般 `conditions` 仍可通过原场景编辑；资源和新的疯狂字段不能通过整份场景覆盖。更正 SAN 为正值不会自动治愈既有疯狂。

一次遭遇复用一个 `CheckRecord`，内部顺序为 SAN → 必要损失骰 → 必要 INT → 必要临时疯狂时长 → 主机症状 → 完成。常数、零损失、大失败最大损失无须额外骰子。普通调查仍最多一个检定请求，SAN 内部阶段不是额外普通行动。已扣减但尚待 INT／症状的遭遇不能取消以逃过后续结算；可以读档回退。

资源只存在 `SessionStateV1.characters[slot]`，新 `sanity` 保存累计、类型、阶段、症状、神话增量及起止历史；`game_minute/game_round/sanity_day` 保存游戏时间。扣减、阶段更新和回执在同一 SQLite 事务内提交。`sanity.dice_fixed` 是只供主机审计的骰点记录，不是资源真值；同一检定阶段重算必须复用该骰点。`sanity.progressed/involuntary/state_changed` 接入 `story_v1`；规则问答仍被排除。

## 存档恢复

| 存档位置 | 恢复行为 |
| --- | --- |
| 检定前 | 恢复当时资源、累计和疯狂；其后 SAN 检定标记为已回退。再次处理同一实际遭遇事件可复用原骰点并重新结算一次。 |
| 待掷阶段 | 恢复该阶段的检定文档及相应资源。例如已扣减后等待 INT，读档保留这次扣减，只继续 INT；待 SAN 则恢复扣减前现值。已经在另一时间线掷过的骰子仍固定。 |
| 结算后 | 恢复结算后现值、历史和完成状态；重复旧点击仅返回既有结果。 |

资源不使用公开知识的单调保留策略。SAN 保存的处理状态会回退，即使原回合后来已经完成；必要时从 SAN 等待之后继续图执行，旧工具回执不替代资源结算。旧档缺少新增字段时使用兼容默认值；主机需通过专用更正确认历史 SAN 是否有效，不能据此推断旧游戏日已经损失多少理智。
