## 实现

- 输入区增加“调查行动／规则提问”。`POST /actions` 的 `category` 默认 `investigation`；`rule_question` 直接进入公开规则答复，沿用身份、运行状态、活动回合互斥及幂等机制。类别、正文、目标、席位或澄清对象改变时使用新请求 ID。
- 规则问答跳过 PlayerIntent、KeeperPlan、行动图及生成模型。精确规则版本命中 `RuleTopicRegistry` 时组织完整主题释义；其他版本、未覆盖问题进入现有规则 RAG。复合问题逐项处理，未知内容不会被已知术语掩盖；RAG 摘录明确标为未确认覆盖全部细节，无有效证据则明确说明未找到。问答 run 仅保存问题和本次公开规则证据。规则说明不授权未实现操作。
- 公开实体按批准 ModuleIR、当前导航及真实公开记录派生 `current_scene`／`historical`／`unknown`。ID 判断身份，多场景绑定按实际场景生效；无位置依据不推断携带、跟随或转移，不公开未来绑定。调查板、KP 与队友使用相同范围投影。候选按目标、真实结果、当前场景及相关性选择，发布再次校验历史限定和 NPC 在场条件。
- 增加只读 `recall` 意图；明确只复述的回顾输入可校正模型误判，并保留原输出与校正审计。生成或校验失败时回退到相关的、经过校验且带历史限定的公开摘录；不创建新事实，不按实体顺序固定取前两个。
- `story_v1` 选择器统一摘要阈值、摘要输入、近期窗口、失败恢复和手动重建。权限过滤先于剧情筛选；保留原 seq，排除初始化、角色／房间管理、检索审计和规则问答。真实角色分配由 `current_participants` 提供。摘要只处理最早未处理剧情的连续前缀；首个事件超预算时记录 pending／stale 和失败次数，保留旧摘要，不跳过该事件。原阈值、每轮一次尝试、退避及停止自动恢复保留。
