## 实现与规则

- 新增非战斗双方对抗：真人操作自己的骰，AI 队友及 NPC 由服务端掷骰。双方可以选择不同属性或技能，数值在创建检定时从角色快照或已批准并绑定的 NPC 准备快照冻结。没有准备数值、不可见、异地或其他房间的对手被拒绝。
- 对抗比较六个等级，同级比较完整数值；完全相同选择僵局，不追加骰。非战斗双失败仍依此比较，并保留双方原失败等级和 `both_failed`，不套用战斗的双失败例外。双方原骰齐备后，行动者先选择幸运、对手后选择，每方一次；AI／NPC 自动接受原骰。全部确认后才发布统一胜负，对抗不能孤注。
- 同一角色两种技能共用一次百分骰，各自按冻结数值和难度判断。KP 在骰前明确 `any` 或 `all`，卡片保留两项等级、阈值和部分成功。幸运修改共用骰点，扣一次资源；符合资格的孤注共用第二次骰，执行一次失败后果。任一分项大失败均不能用幸运或孤注；已花幸运与孤注互斥。
- 保留既有线索的单技能门槛：对抗的相对胜利或 `any` 组合不能隐式替代它，KP 须先填写替代依据；`all` 组合可以保留匹配的第一技能及难度要求。该规则同时在行动政策与创建检定服务中验证，最终通过后才沿用原线索揭示流程。
- `CheckRequest` 增加默认空的 `opposed`／`combined`，`PendingCheck.compound` 保存参与者、固定数值和阶段，一个 `pending_check_id` 管理整次尝试。复用原串行图、检定卡、聊天、权限、房间事务、固定骰账本及存档。没有新增普通主机审批。
- NPC 准备工作台支持有来源的 `check_stats`，模型生成草稿不能填写数值。公开卡移除 NPC 数值来源说明；已绑定房间不受之后的准备修改影响。前端显示双方掷骰、当前选择人、资源变化和最终胜负，组合卡显示两个分项；时间线保留最终复合卡，线索面板继续沿用。
- 自由行动规划增加两类提案字段、可用对手和生成语法约束；该约束只用于新增检定接入。没有开展通用自然主持、提示词或检索优化。原普通检定、SAN、旧提案和旧存档保留兼容入口。

本地依据已读取并渲染核对：`data/rules/克苏鲁的呼唤第七版规则书1907.pdf`，对抗 PDF 78–80（印刷 77–79）、组合 PDF 80（79）、孤注 PDF 74–75（73–74）及大失败 PDF 77（76）、幸运 PDF 85（84）。[简短规则与接口说明](compound-checks.md)列明逐条来源、规则解释、幸运顺序的项目约定和请求示例；`SOURCES.md` 同步补记来源。
