## 实现边界

服务端`equipment.py`是车卡与主机准备唯一内建目录。装备API返回`weapon_template`作展示；主机通过`weapon_loadout`仅传模板ID和初始状态，服务端生成实际武器ID、读取参数。原主机`weapons`明确配置入口保留。攻击／反击／装填和KP候选使用实例ID，不使用模板ID。NPC缺对应技能时422；冻结旧卡可以保管缺技能武器，但不能用它攻击或取得枪械先手，不补写技能或退回斗殴／手枪。

`EquipmentEntry`两个新增字段沿现有角色模型贯通，不引入新导出格式版本。每条quantity为2、初始3／8，会生成两个不同实例、每件3／8。首次`initialize_equipment()`读取配置，随后由原`sync_equipment_weapons()`和战斗reducer同步当前状态；重复开始被拒绝，再次初始化不补满，目录后续变动也不重建已冻结武器。备弹仍按武器记录，没有独立弹药仓库或购买系统。

有起始遗失／选择规则时整张卡标为`module_pending`，实际物品仍由模组规则结算，包括《常暗之厢》。本批用隔离规则夹具验证优先级，没有改动或重跑批准包的长团流程。普通用品描述不授予数值效果。

新增`Weapon.uses_db`只区分完整DB和无DB：矛在本地两书均是1d8+1，未列DB；旧武器缺省保持原近战加DB行为。大型剑贯穿在1907与手册有差异，明确沿用本项目1907表√，来源中保留冲突记录。没有凭记忆纠正原文。旧武器缺少`template_id/base_range`仍可加载，显示射程未记录，不从目录更新旧武器。

距离档位只沿用已有规则，不做地图测距。普通近战与单发范围外，12组具体剩余依赖列在覆盖表：半DB／投掷、跨轮装填、混合骰式、自动火力、多发／双管、霰弹、爆炸、火焰、链锯、绞索、电击／催泪、其它年代枪型及任意自定义。它们不是完整武器总数统计。
