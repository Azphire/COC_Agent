# 检定与叙事政策（第八批）

`KeeperPlan → 服务端裁决 → 工具／骰点 → KeeperNarration` 仍为两阶段流程。模型只提出行动；检定服务在真实创建时再次验证，不能绕过裁决器。

## 检定必要性

`CheckProposal` 继承旧检定参数，增加目标实体、必要性 required／optional／unnecessary、不确定因素、成功效果、失败后果、实体依据、规则 topic、风险原文及重复声明。旧 JSON 可读，缺失的新字段默认不能授权额外检定；生成 schema 要求模型明确输出关键字段。

`CheckPolicyEvaluator` 要求：角色卡存在该属性或技能；目标在当前场景可见范围；有批准实体检定配置，或玩家原文含明确风险且引用已实现 `coc7.skill_check`；不确定性非空；成败效果不同且非空；同状态未完成相同目标、角色、种类和技能的检定。普通观察、交谈、移动、等待不因附近有检定线索而掷骰。实体配置要求玩家明确调查该目标或通过界面指定目标，不能由模型把泛泛观察变成调查隐藏细节。

模型的 `is_repeat_attempt` 不决定是否重复。SHA-256 指纹由当前场景、导航 revision、模组状态、公开实体状态和角色卡构成；聊天、叙事、经过几个 cycle 或再次提问不会单独解除限制。指纹保存在现有 CheckRecord JSON，随存档／读档保留。通过检查只授权骰子，不自动实现伤害、理智或时间消耗。

提案的 target 与 basis 同指一个已批准 requires_check 实体时，服务端可补齐旧接口的 clue_id 别名；不会补写不存在的检定配置或虚构目标。成功时才继续批准的线索公开；失败不会公开内容。部分动作被拒绝时保留合法动作，把原因交给叙事，不重建完整计划。

## 实体访问

复用 `reveal_conditions.access_policy`，不增表、不改旧表列。

| 策略 | 行为 |
| --- | --- |
| automatic | 无额外门槛的批准公开内容；仍受当前范围与权限约束 |
| requires_check | 必须有 successful_check 配置并实际通过匹配检定 |
| requires_condition | 必须有可验证场景／前置实体条件且已满足 |
| host_review | 转为主机审阅；匹配目标批准后才允许访问 |

旧实体有 successful_check 则推导 requires_check；有前置实体或人工条件说明则推导 requires_condition；其余默认 automatic。已有 note 无法自动验证时沿用主机判断。显式配置自相矛盾或缺少所需条件不能批准。

## 公共文本

规则集显示解析返回内部 skill_id、中文 display_name、ruleset_id 和可选 english_name。内部 ID 供执行，公开事件 name 改为显示名；公共 JSON 去除线索依据和策略指纹。检定结果保留骰点、目标、实际难度、成功等级、奖惩骰及服务端 display_text，模型不参与判定或修改骰点。

NarrationValidator 验证所选 claim 必须在当前 run 有效、公开且受来源版本和权限约束；实体已公开；场景引用只能为当前场景；检定和转场必须真实完成；禁止内部 snake_case、工具／系统错误、相反成败描述。自由生成的新剧情不直接公开：叙事正文来自验证过的公开 claim，再由服务端加自然行动引句及真实检定结果。

模型格式与语义共用最多两次请求（初次加一次修复），不会层层叠加重试。超时或修复失败后，确定性中文 fallback 使用行动类型、真实检定、已发生的公开／转场和当前公开摘要；不会再请求模型或执行工具。OOM 继续上抛，不伪装成成功。没有规则依据时明确需要主持人裁定。模型说需要主持人判断但给出了有效公开 claim 时，已验证的内容仍可发布；尚未确认的内容不会加入。

## 规则选择

Registry 绑定 mechanic ID、版本、来源 hash、PDF 页码、章节、适用条件和简短释义。绑定本地1907版精确 hash 才启用：属性／技能72–73、难度73、大成功／大失败77、奖惩骰79。详见[来源核对](../backend/app/rules/definitions/SOURCES.md)。该路径不执行 FTS。

未知机制或未匹配来源版本使用现有 RAG；从计划及玩家规则问题抽取具体概念，每个概念独立检索，再按来源、hash、chunk 去重。证据先做权限过滤，再检验词汇相关性和预算。每条 RetrievalRecord 记录 structured／rag、概念、返回候选、实际注入、排除及原因；claim 仅能引用最终注入的裁剪文本。机制 ID 会规范为中文概念，不把模型发明的工具 ID 当规则问题。

## 调用与恢复

普通行动目标为计划一次、叙事一次。TeammateEligibilityPolicy 仅在本轮新线索／实体、场景变化、真人直接点名交谈、与短期目标相关的检定或事件时触发；其他情况直接存内部 pass，不建立模型 run，不输出台词。每轮至多一个符合条件的队友获得调用机会；保留第七批针对重复行为的一次修复，异常时可能出现第二次队友请求，均计入日志。

摘要只在未摘要事件达到 `AGENT_EVENT_WINDOW + SUMMARY_EVENT_THRESHOLD`（默认25+20）或序列化上下文达到12000字符时尝试；近期窗口留给正常上下文。每轮最多一个摘要尝试，已有失败恢复仍按退避与上限处理；主机手工重建可越过阈值。初始化房间／车卡事件也占预算，所以摘要可能较早出现。

场景选段之后还核算完整上下文（含导航审计和公开实体ID）的大小，必要时确定性缩减当前场景选段，为规则路由字段留余量；不增加模型请求或扩大模组检索范围。摘要提示区分角色发布与分配，禁止推断事件列表之后的安排。

`MODEL_THINK` 映射到本地 Ollama `/api/chat` 的 think 布尔参数；默认 false 延续原适配器行为。思考文本从不复制到返回对象或公开日志。每次实际请求的阶段、成功／错误、token 用量和耗时继续保存在 AgentModelCall，并累计到 cycle 状态。主机能看计数、策略和来源审计；玩家只看公开行动、自然结果、检定及等待状态。

## 边界

风险识别为保守的中文词汇交叉验证，不是完备语义理解；拒绝也可能需要主机裁定。词汇相关性过滤不保证整段都只谈一个规则。精确 claim 约束优先保证事实与权限，长段场景复述和语言变化仍有限。SAN 与普通检定的幸运／孤注后处理已接入，见 [第十一批规则与接口](check-settlement-and-encounters.md)。完整战斗、伤害和任意文字条件推理仍未自动化；成功文案不能授予额外行动权限。
