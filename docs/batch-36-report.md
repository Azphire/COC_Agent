## 实现

- 扩展现有 `TurnFocus.requests`，保存每段请求的对象、原文及位置、请求类型和词法操作边界。KP在既有规划调用中解析；兼容旧计划，不增加分类模型。
- 两名直接请求者均进入原串行调度，每人一次决策及至多一次修正。无人点名时保留一个主动参与名额；子周期不递归触发队友。
- `BehaviorState` 保存待处理请求、任务阶段、子周期ID及真实结果引用。技术失败不再被写成角色口中的“我这次还没有执行你的请求”；保存恢复保留待处理请求。
- 问意见只要求答话；礼貌委托允许队友提出自己的尝试。拒绝、未调度、生成失败、提出动作、受阻及有反馈的完成分别记录。没有实际反馈的提案不计完成。
- NPC提示区分玩家说法、来源事实、批准证词和旧对话；逐项列出本次问题。针对复述问题保留一次定向修正，失败后尝试保留单独验证通过的旁白或NPC回答。
- 观察无需世界状态变化；已有公开目标的观察不再因多余的揭示/操作提案被整体写成失败。转场的词法边界仍受校验。
- Ollama格式/语义验证失败保留实际输入输出token计数及可审计的回答正文；不复制thinking通道。
- NPC最近对话及队友近期输出改用当前存档分支，避免读档后把已撤销的未来事件带入提示。物理照顾对象不再经旧NPC扫描覆盖已解析的请求对象。
- NPC在原叙事调用中逐问题保存原文证据、陈述/推测/未知和回答，不增加评审模型。该约束只验证来源摘录和结构，仍不能证明自由文本语义正确；实际误述必须另列质量失败。
- 无操作回执且并非正常成立的只读观察时，队友任务最多记为 `attempted`，不因KP描述了尝试就记为完成。结果在下一次可用机会触发一次重新判断，仍共用单个主动参与名额。
- 保留8192上下文；应用字符预算没有作为token数报告。提示去除重复公开事实、KP专用检索词及旧可选材料，修正提示仍保留原请求和真实结果。
- 读档保留已公开事实，但从撤销进度揭示的内容标为历史信息，即使它绑定同一场景也不能作为当前观察。原事件和公开实体不删除；修复了旧存档短场景中未来结局混入回退旁白的问题。
