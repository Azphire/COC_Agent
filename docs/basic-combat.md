# 基础战斗：规则与接口

## 第31批：自主资格与受限等待

`capable()` 继续只表示原身体／伤势资格，供目标和战斗存续使用。新的自主资格从 `SessionStateV1.characters` 读取SAN与疯狂，战斗参与者不复制SAN。SAN0、永久疯狂、等待症状和发作角色不能新发起攻击、装填、主动治疗、等待或脱离；判断在新骰点、弹药、资源和时间效果之前执行。无SAN模型的NPC保留原行为，受限但身体仍符合条件的调查员仍是合法伤害／治疗目标。

顺序推进跳过不能自主行动的角色，保留其目标资格；SAN更正与恢复会重新核对当前顺序。AI在排队和执行前都核对运行时，受限者不产生模型决策。跨轮推进产生的强制CON优先结算；真人原有强制CON确认仍可用，受限角色不因不能花幸运而多等一次结果确认。

`POST /combat/step` 增加唯一的主机受限操作 `resolve_restricted`，参数仍是当前 `action_id/stage`，另须非空 `reason`。它只接受**当前阶段的参与者已受理智限制**的情况，不接受武器或幸运花费，健康真人不能使用此入口，也不能以此创建新动作：

| 当前等待 | 固定处理 |
| --- | --- |
| 尚未选择防御 | 不进行新的自主闪避／反击／掩体骰，按不防御继续原攻击 |
| 防御待骰且该骰从未产生 | 不进行新的自主防御；保留已发生的掩体行动消耗，继续原攻击 |
| 攻击／治疗待骰且该骰从未产生 | 停止尚未执行的自主动作，保留已经发生的其他阶段与回合结算 |
| 已有原骰／等待幸运选择 | 接受原结果，不花幸运；需恢复的历史固定骰复用原账本，不重掷或退款 |
| 强制伤势CON | 继续原强制检查及其结算；正常本人确认也保持可用 |

原因保存在动作的 `restricted_resolutions` 和主机事件 `combat.restricted_resolved`。原动作的资源回执、固定骰键和阶段决策继续负责重试与读档幂等。原本人可以接受已掷结果，但不能自行选择新防御、幸运或新的攻击／治疗骰；AI也停在受限的自主阶段。UI同步显示限制和主机固定处理，普通健康角色仍沿原权限直接操作。

此处“不防御／停止未执行动作”是本批针对受限阶段的最小软件处理策略，不声称覆盖规则书中所有具体疯狂症状；症状本身及已确认后果仍沿原主机理智处理链。来源继续沿用已核对SAN归零与发作条款，详见[理智说明](sanity-and-insanity.md)及[第31批报告](batch-31-report.md)。

第十六批补充：有完整来源数值的准备实体可携带 `combat_template`，在房间绑定/场景进入时自动映射稳定身份的Combatant。模板数值与房间HP、伤势、弹药分离；回访只同步位置，不刷新资源。当前场景及实际可见性限制候选和玩家投影。缺HP、CON、攻击/伤害等必需值时，主机面板列出缺项，不能自动补普通人模板。常暗原稿即有此阻塞，详见 [第十六批报告](batch-16-report.md)。

本批沿用本地《克苏鲁的呼唤第七版规则书1907.pdf》。SHA-256 为 `bc8455d443ec4c64ae86ec2d6e6637889eff2cd59a4cc4686076e95b130d08dc`。下列 PDF 页码从 1 起算，印刷页码均减 1。没有引入其他版次或凭记忆补充规则。[非战斗对抗及组合接口](compound-checks.md)继续适用。

## 已核对的规则

| 项目 | 实现口径 | PDF 页 |
| --- | --- | --- |
| 通用对抗 | 先成功等级，同级比较完整技能／属性值，仍同则僵局；双失败仍比较。禁止孤注。 | 78–80 |
| 组合 | 同一角色两技能共享百分骰；骰前选择全部／任一通过，各自显示等级。幸运改共享骰并只扣一次；合法孤注也共享新骰。 | 80、74–75、85 |
| 顺序 | DEX 降序，同 DEX 战斗技能高者先；准备好且射击的枪械 +50 DEX。完全相同按稳定 ID 排序是项目约定。不射击时放弃枪械先手，插回尚未行动者的通常顺序。 | 87、96、109 |
| 攻击／闪避 | 攻击的成功等级必须严格更高；平级闪避成功，不比较完整技能数值。 | 88 |
| 攻击／反击 | 成功等级相同由攻击者获胜；双方均失败不造成伤害。反击成功也造成武器伤害。 | 88、107 |
| 伤害 | 普通近战为武器骰＋DB；枪械不加 DB。攻击极难／大成功：非贯穿武器取武器与 DB 最大值；贯穿武器再加一组武器伤害骰。反击不享受极难额外伤害。四倍射程处仅大成功享受贯穿。 | 88、96 |
| DB | STR＋SIZ：2–64 为 −2；65–84 为 −1；85–124 为 0；125–164 为 1d4；165–204 为 1d6。调查员直接复用已确认角色快照。 | 27 |
| 数量优势 | 防御过一次后，同轮后续近战攻击获得一枚奖励骰；新轮清空。本版只处理每轮一次行动的普通参与者。 | 92 |
| 单发射击 | 基础射程常规、两倍困难、四倍极难；抵近（DEX/5 英尺）奖励骰。射击不是与闪避的普通对抗。 | 96 |
| 寻找掩体 | 防御者先做闪避检定，成功给射击一枚惩罚骰；无论成功与否失去下一次行动。也可选择不找掩体。 | 96 |
| 弹药／故障 | 每次实际击发尝试扣一发；原骰达到故障阈值则枪械故障，幸运不能消除。基础装填一次行动最多装两发散装弹；尚不建模备用弹匣。 | 97、99 |
| 护甲 | 净伤害 `max(0, 原伤害−护甲)`；魔法、毒素、溺水等由明确后果设置 `armor_applies=false`。 | 92 |
| 伤势 | 按**抵扣护甲后的单次伤害**判断：`2×伤害 >= 最大HP` 为重伤、倒地，HP 尚大于零时立即 CON 判昏迷；`伤害 > 最大HP` 直接死亡。恰好最大HP为重伤并在 HP0 时濒死。HP 不为负；普通累计轻伤到0昏迷、不自动濒死。 | 101–102 |
| 濒死 | 重伤且 HP0，立即昏迷，从下一轮结束开始逐轮 CON，失败死亡。战斗外由主机逐轮推进，禁止跳过几分钟。 | 102 |
| 急救 | 一小时内，常规成功恢复1HP；通常同次伤势一次尝试，后续需孤注裁定。濒死可重复急救，成功为1临时HP，按小时 CON 维持稳定；失败回到0HP濒死。稳定者需要医学，不能反复急救刷HP。成功急救可唤醒非濒死昏迷者。 | 55–56、101–102 |
| 医学 | 先稳定濒死者，至少一小时；成功以1d3正式HP替换临时1HP并去掉濒死状态。普通伤者则在已有HP上增加1d3。受伤当天之后为困难；每次伤势不允许反复普通医学掷骰。HP 恢复到一半以上解除重伤。 | 55、102 |
| 幸运／孤注 | 房间启用幸运后，可用于战斗技能、闪避及 CON；不修改大成功、大失败、枪械故障或伤害骰。战斗攻击／防御没有孤注入口。AI/NPC默认接受原骰，真人自行选择。 | 85、88、99、107 |

大失败阈值继续复用仓库已经核对的本地译本口径（以本次成功上限判断，见 `SOURCES.md`），没有借本批改写原规则。HP0 后继续攻击、处决、特殊生物多次攻击、战技／擒抱、偷袭、连射、自动火力、霰弹与特殊射程、完全掩蔽、移动射击、可选俯卧奖惩骰和长期恢复均不在自动结算范围。`end` 表示在存在退路且未被压制的基础场景脱离；复杂逃脱须主机判断。

基础治疗没有新增“急救／医学孤注”或双人合作治疗专用流程：普通急救失败后的再次尝试、医学重复尝试由主机记录例外裁定，不能用普通治疗接口反复重掷。濒死急救的规则允许重复已单独支持。游戏日沿用 `sanity_day` 的主机日界，分钟及轮数沿用房间时间；每轮长度不强行折算成分钟。

## 数据与接口

所有路径均位于 `/api/rooms/{room_id}`，使用已有成员／主机鉴权。

| 路径 | 作用与关键字段 |
| --- | --- |
| `POST /actions` | 原自由描述入口。战斗意图由当前模型分类；普通对话、调查交回原串行图。实际攻击进入同一 combat reducer。 |
| `POST /combat/setup` | 主机准备；`expected_revision`、`reason`、`member_id` 或 `npc` 二选一。角色沿用快照 HP、DEX、CON、技能、DB；NPC 明确填写数值和 `source`，无需完整车卡。战斗／待裁决时禁止改数值。 |
| `POST /combat/action` | `actor_id, target_id, operation, weapon_id, reason, client_request_id, turn_key`。操作包括 attack、first_aid、medicine、reload、pass、end。首次攻击自动建立顺序；发起者不一定先行动。 |
| `POST /combat/step` | `action_id, stage, operation`；defense 阶段选择 dodge/fight_back 或 cover/take，roll 阶段确认掷骰，choice 阶段 accept/luck。反击附 `weapon_id`，幸运附 `spend`。 |
| `POST /combat/damage` | 主机已确认的规则外伤害：`target_id, client_request_id, amount, armor_applies, reason`；进入同一护甲／HP／伤势入口。 |
| `POST /combat/control` | 主机 end 确认停战，或 advance 推进伤势时间；`expected_revision, minutes(0–60), reason`，0分钟表示推进一轮。 |
| 原 `/checks/.../push-review` | `consequence.kind=damage`，骰前固定 `damage_formula` 和护甲适用性。失败后自动进入统一伤势处理，再恢复原叙事。 |
| 原 `/checks/.../consequence`、`/sanity/manage` | 已确认后果可携带 `damage`、`armor_applies`；SAN仅允许确认 symptom 时伤害。叙事不能改数值。 |

最小武器为 `id/name/skill/kind/damage/impale/quantity/ammo/capacity/reserve/malfunction/jammed/ready/source`，第29批新增可选 `template_id/uses_db/base_range`。`id`是实际实例，模板ID不能替代它进行攻击或装填。公式支持整数或单组`NdM±K`。原冻结武器按原值读取，不从新目录补写；旧近战默认仍加DB，旧射程为空。矛按本地两表1d8+1、不加DB，其他新剑斧加完整DB。

主机面板与车卡共用`/api/character-equipment`：14种武器加徒手，新增剑、斧、矛及普通单发步枪。来源与33项装备的逐项覆盖见[装备覆盖表](equipment-coverage.md)。主机setup可用`weapon_loadout:[{template_id,ammo,reserve,ready}]`让服务端解析模板并生成实例；原明确`weapons`入口保留，二者不能混填。NPC按所选武器填写对应技能，调查员沿用冻结技能；缺技能不能退回斗殴／手枪。基础射程只展示，面板距离档位传原`range_band`，不引入地图测距。

`CharacterRuntimeV1` 增加 `hp_max/armor/injury/weapons`；`SessionStateV1.combat` 保存参战者、轮次、顺序、当前行动、待裁决事项、冻结依据和操作回执。旧存档缺失字段时默认无战斗、无伤势、护甲0、徒手；最大HP从角色派生值补齐，不改变原当前HP。

房间返回额外的 `combat` 视图；真人只看自己的完整数值，其他角色由 `stats_public` 决定，隐藏NPC不会出现在公开顺序。主机保留完整资料与来源。公开 `combat.resolved` 只含可见结论；本人收到 `combat.receipt`，完整结果放 `combat.audit` 主机事件。

## 串行结算与恢复

一次攻击是一个事项：固定参与者和武器／技能依据 → 等防御 → 攻防原骰与幸运确认 → 胜负 → 伤害／弹药／HP → 必要 CON → 公开叙事。真人仅能操作本人；主机可控制主机管理席、AI和NPC，不能代替远端真人选择防御。

骰点以 `combat.dice_fixed` 追加事件保存，键为事项＋阶段并核对依据。效果回执随存档恢复；恢复到伤害之前可以重新应用同一伤害，使用原骰，最终HP等于当时结果。阶段选择、伤害和请求ID校验拒绝同ID换内容；相同请求重复提交不重复扣HP、幸运或弹药。已有固定骰的事项不能直接取消；明确读档仍沿用原存档分支及固定骰账本。

结算已完成但叙事尚未完成时保留可存档窗口。重启恢复等待阶段，叙事失败后重试只重试叙事。自动角色行动也用同一 reducer；错误行动停止为可复核异常，避免不断重试和消耗模型预算。
