## 流式路径与发布边界

Ollama原生NDJSON与OpenAI兼容结构化流在原请求中收集完整结果并回调content；保留非流式，沿用原有最多两次尝试（一次结构修复）和回合调用预算。没有额外润色调用，也没有生成后打字机。跨chunk JSON字符串、转义、Unicode代理对、重复键、伪嵌套同名字段、截断、超时及取消均有定向测试；thinking不进入正文通道。

动态契约指定`public_narration`或映射为正文的`observed_detail`；生成schema将已有正文属性排在前面，避免先生成附属字段增加正文等待。本轮公开实体、来源、结果、库存、导航及私密材料在生成前冻结；每次校验“已接受前缀＋候选完整句”，并按最终恢复的同一顺序绑定冻结的检定与转场引用。专用`validate_prefix`只跳过整篇必须交代完整结果的覆盖要求，仍检查私密内容、来源文字、实际结果、资源、通行和照明；不使用`partial=True`冒充前缀校验。HO、隐藏材料、思考标记、原始JSON和内部ID不会作为增量发布。完整恢复、动态契约和完整发布校验仍照常执行；回退保留正文也经过相同私密检查。NPC获准披露证词的原有权限不扩大到KP正文。

以下仍缓冲到完整结果：`readonly_recall`和历史回顾（服务端恢复原文）、NPC／队友回应、规则依据分支、依赖后续引用或尚未公开信息的句段、无法通过前缀校验的句段、没有句末标点的尾部。普通公开外观描述可提前显示；关键事实需要已固定的公开来源。字面与结构校验不等于任意自然语言语义正确性的证明。

回顾只把本轮服务端筛选的公开`fact_evidence`原文加入可用来源。既有模块私密门把非当前场景统一视为隐藏，本批对严格等于本轮服务端完整恢复结果的文字作窄例外，防止旧公开场景原文被误拦；未选旧场景、模型改写及附加HO均不获授权，其余完整结果、HO和内部标识检查继续执行。
