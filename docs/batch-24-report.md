### 修复路径

- `generation_contracts.py` 将当前可调查、带条件的目标纳入 KP 可选目标。玩家不必知道隐藏线索名称或实例 ID。

- 调查计划若承诺发现、却只申请未关联线索的检定，进入既有一次有限计划修复。KP 根据当前对象选定目标及后果，或对多目标澄清；独立的身体风险检定仍保留。
- 绑定后继续使用现有 CheckPolicy、ActionAdjudicationService 和恢复执行链。骰前批准检定与对应揭示，成功执行那一项，失败保留原骰与未揭示状态。没有场景级“一骰全开”，也没有将发现自动写成持有。

## 2. 正式包导入

新增 `backend/app/preparation/packages.py`，从 `module_package.py` 抽取静态校验和导入。主机 `POST /api/module-preparations/import` 接收 UTF-8 JSON 文件（15 MB 上限），直接使用当前应用的准备、结构、知识与数据库服务。API 不嵌套 TestClient，不重建模型或更换凭据。CLI 保留显式 `--directory` 的独立应用用途，调用同一个导入服务。

### 校验、审阅和版本

- 核对格式、来源文件 hash 和汇总 hash、安全相对路径、知识块及相邻引用、IR 来源版本、完整来源块覆盖、节点／实体／交互／SAN／修正引用、唯一初始节点和转换条件。
- 按包声明检查必需 NPC 操作。原稿缺失、改动及文件清单变化返回具体原因。绑定前再核对原稿及批准结构版本。
- 准备、实体、节点绑定、转换和批准快照在同一游戏数据库事务内发布。后段失败回滚，不能留下可开团版本。知识／IR 是独立派生缓存，已验证的缓存可能保留，不构成可绑定产物。
- NPC v1 的批准 ID、补充内容 hash 和对应实体数值核对通过即可复用，无需再次批准。未登记的新补充、来源数值变化和无批准记录的主机新数值留在原有实体审阅流程；缺少必需操作值时不能批准开团。
- 相同包内容且当前导入实体／结构未变化时复用版本；新内容或后续编辑过的内容创建新版本。已绑定房间继续使用冻结快照。加入当前导入内容指纹，防止结构编辑重新批准后误复用旧包标识。
- 只翻译实体引用字段，不改写正文、标题、SAN 效果 ID 或数值来源。旧脚本的全字符串替换会误改与实体键同名的内容，本批一并修正；CLI 导出也共用引用转换。
