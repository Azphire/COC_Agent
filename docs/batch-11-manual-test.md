# 第十一批：自己跑的本机测试指南

适用于当前仓库与本机保留的第十一批验收资料。编写时 HEAD 为 `5ffdc3f`，已包含 SAN 自动触发、幸运消耗和孤注一掷。

推荐顺序：**复制隔离库 → 新建本地真人房间 → 幸运与读档 → 自动 SAN → 另建房间尝试孤注**。只需一个浏览器窗口；本地真人的玩家选择由你在主机界面操作。本指南包含《常暗之厢》2号车厢局部剧透，复用已批准准备，不代表完整模组流程。

## 1. 准备独立测试目录

所有命令均在仓库根目录的 PowerShell 执行。使用现有虚拟环境、前端依赖和本机 Ollama `qwen3:8b`。先停止你自己正在运行的本项目后端、前端，确保 8000、5173 端口可用；保留 Ollama 后台服务。

首次执行以下整段。它通过 SQLite 备份接口复制三个数据库，再复制验收资料；目标已存在时会停止，不覆盖先前手测结果。

```powershell
Set-Location D:\Codes\COC_Agent
@'
from contextlib import closing
from pathlib import Path
import shutil
import sqlite3

root = Path.cwd().resolve()
base = root / ".cache/batch-11"
source = base / "real-smoke-d16734d1326d4bdcab49324a4be7af8b"
target = base / "manual-play"
assert (root / "backend/scripts/check_batch11.py").is_file(), "Run from repository root"
assert target.resolve().is_relative_to(base.resolve())
for name in ("game.db", "knowledge.db", "checkpoint.db"):
    assert (source / name).is_file(), f"Missing acceptance database: {name}"
assert (source / "data").is_dir(), "Missing acceptance data directory"
target.mkdir(parents=True, exist_ok=False)
for name in ("game.db", "knowledge.db", "checkpoint.db"):
    with closing(sqlite3.connect((source / name).as_uri() + "?mode=ro", uri=True)) as src:
        with closing(sqlite3.connect(target / name)) as dst:
            src.backup(dst)
shutil.copytree(source / "data", target / "data")
print(f"READY: {target}")
'@ | backend/.venv/Scripts/python.exe -X utf8 -
```

看到 `READY: ...\manual-play` 后继续。以后重启同一测试直接执行下一节，跳过复制步骤。所有游戏操作都写入 `.cache/batch-11/manual-play/`，原验收记录与用户库保留。

若提示缺少验收数据库，说明本机缓存不完整；本指南的快速路线依赖这些未提交到 Git 的资料。此时需按 [模组准备说明](module-preparation.md) 在独立库中建立并批准准备，不能直接用空库代替。

## 2. 启动前后端

终端 A，在仓库根目录运行：

```powershell
backend/.venv/Scripts/python.exe -X utf8 backend/scripts/check_batch11.py --serve .cache/batch-11/manual-play
```

这里必须保留 `--serve` 及目录参数：这个模式只启动隔离后端。省略参数会运行自动验收，自动提交行动和掷骰。

终端 B，也在仓库根目录运行：

```powershell
npm.cmd --prefix frontend run dev
```

使用 `npm.cmd`，避免本机 PowerShell 的 `npm.ps1` 丢失转发参数。前端配置已固定监听 `127.0.0.1:5173`，无需再传 `--host`。终端应显示 `> vite` 和 `Local: http://127.0.0.1:5173/`；若显示 `> vite 127.0.0.1`，IP 被误当成网站目录，会导致首页 404，请停止该前端并按上面的命令重启。

打开 <http://127.0.0.1:5173/#/rooms>。建议用单独的浏览器窗口或无痕窗口，避免混用以前的房间凭据；整个测试期间保留这个窗口。

“主机解锁”输入以下**隔离启动器专用测试密钥**：

```text
isolated-browser-smoke-host-key-no-user-secrets
```

这是脚本内置的本机测试值；本路线不使用页面提示的 `host_key.py --show`，也不修改 `.env`。在“系统状态”确认后端与数据库正常，模型为本机 Ollama `qwen3:8b` 且可用。健康检查通过本身不等于模型可用。

## 3. 创建新的测试房间

不要直接继续列表中的旧验收房间：它的 Luck 已消费，Clicker 的首次遭遇也已经结算。

1. 创建房间，名称填 `手测11-A：幸运与自动SAN`。
2. 在“玩家与席位”填写 `手测调查员`，控制器选 **本地真人**，点击“添加席位”。
3. 在“房间调查员”选择已有的 **SAN验收调查员**，点击“发布角色”；将它分配给 `手测调查员`。该卡聆听 20、初始 Luck 50、SAN 50。
4. 在“模组准备与主机审阅”的“批准版本”选择 **第十一批常暗之厢局部SAN验收 · v8**，点击“绑定准备版本”。如有同名项，准备 ID 应为 `3c19bc7a-2a79-454a-87ed-8b2e37dd96ad`。
5. 在“房间知识来源”勾选本地 **1907** 第七版规则书，本地模组选 **常暗之厢**，点击“绑定所选版本”。无需重新索引或生成准备。
6. 在“AI 与模组设置”给 **AI KP** 绑定已有 **本机KP** 档案。此次不用添加 AI 调查员席位；AI 会默认接受原结果，不适合用来手测幸运选择。
7. 点击 `准备 · 手测调查员`，再点击“开始游戏”。确认场景为 **2号车厢入口（局部验收起点）**，SAN、Luck 均为 50。
8. 在“理智与疯狂”点击 **启用幸运消耗可选规则**。应显示“已启用”。必须在提交行动前启用，等待检定时不能切换。
9. 在行动区的“真人行动席位”选择 `手测调查员`。

本准备的前提是：调查员已携带光源，先前见过7号车厢尸体；这里只测试首次目睹 Clicker。声音细节的聆听检定是验收时主机批准的测试条件。

## 4. 普通检定、花幸运与存档续算

先展开“模组准备与主机审阅 → 批准实体与隐藏状态 · 仅主机”，找到 **车厢内的声音**，点击该实体的“主机公开实体”。这表示你确认角色能听到喘息声；辨认细节仍需批准的聆听检定。

输入类别选“调查行动”，提交：

> 我冒着暴露位置的风险，靠近车厢内的声音，仔细辨听喘息声中隐藏的细节。按主机批准的条件申请普通聆听检定。

声音不是 NPC，界面的“交谈目标”下拉框不会列出它。保留上述完整实体标题，服务端可在当前可见范围唯一匹配。等待回合出现普通聆听卡，再点击 **掷骰查看原结果**；底部“聊天与掷骰”的通用骰子按钮不属于这次检定。

若有合法后处理选项，应看到：

- 原骰点、原成功等级，以及 **尚未最终裁决**。
- **接受原结果**，以及符合资格的幸运下拉框／孤注申请。
- Luck 仍是 50；此时尚未执行依赖该检定通过的后果，也不应已经出现成功叙事。

先在这个等待阶段做一次重启：

1. 点击“暂停游戏”，在“存档”创建 `A1-原骰已出待选择`，记下原骰点。
2. 终端 A 按 `Ctrl+C` 停止后端，等待进程退出，再执行同一条 `--serve .cache/batch-11/manual-play` 命令。终端 B 保持运行。
3. 刷新房间；必要时重新用测试密钥解锁主机。点击 `载入 · A1-原骰已出待选择` 并确认，再点击“恢复游戏”。
4. 应恢复同一个待选择检定、同一个原骰点，Luck 仍为 50，而不是重新掷骰。

然后在“幸运消耗（可选规则）”选择一个合法花费，点击 **确认扣除 Luck 并结算**。建议先选花费 **1**，方便核对：原骰保留为 `R`，最终结果为 `R−1`，Luck 为 `50→49`。下拉框已经列出各花费对应的成功等级和通过情况。

**降低骰点不保证通过。** 例如聆听20、原骰86，花1点后的85仍然失败；这也是有效的幸运消费测试。不要使用“资源更正”来代替花幸运。

等待当前回合完成后，暂停并创建 `A2-已扣Luck`。载入此档并恢复，确认 Luck 仍为49、原骰与最终结果都保留，没有再次扣点；刷新后已结算卡也不再提供改选按钮。只有主动载入消费前的 A1，Luck 才应按资源回退语义恢复到50。

若骰点没有合法幸运选项（例如大成功、大失败或无法继续降低），按实际可用选项完成该检定，并记录“本次未自然出现幸运消费分支”。不要改骰点或重复读档刷骰；仍可继续下一节测试 SAN。

## 5. 自动 SAN 与 SAN 等待阶段恢复

确认上一回合已完成并且房间正在运行。展开主机实体列表，找到 **Clicker**，点击它的“主机公开实体”，表示光源已照到其可见外形。

**仅公开实体不应立即让所有角色扣 SAN。** 下一步由调查员实际观察，才能匹配本准备的 `action_target` 遭遇。

先做一个反例：输入类别改为“规则提问”，提交：

> SAN 检定能花幸运吗？

应得到规则说明，SAN 不变，也不出现新的遭遇检定。

随后改回“调查行动”，“交谈目标”选择 **Clicker**，提交：

> 我用已有光源照向车厢中段，仔细看清 Clicker 没有眼睛的上半部头颅。

等待服务端处理。预期自动出现 SAN 检定卡，时间线显示 **遭遇自动触发**；受影响对象是这次行动的调查员。无需在行动文字中请求 SAN。

此处不要使用“理智与疯狂”里的 **发起已批准 SAN 遭遇／确认实际遭遇，等待掷骰**。如果必须通过这个入口补发，本次自动触发测试就没有通过。若出现“主机确认实际 SAN 遭遇”，记录为“系统发现后转主机审阅”，核对条件与对象；它也不等同本配置预期的直接自动发起。

在 SAN 卡尚未掷骰时：

1. 暂停，创建 `A3-自动SAN待掷`。
2. 按上一节方法停止并重启终端 A，载入 A3，恢复游戏。
3. 确认恢复的是同一待处理 SAN，SAN 现值尚未被扣除。
4. 在检定卡点击 **确认当前阶段：san**。若随后出现 `loss`，点击 **确认当前阶段：loss**。按当前卡片逐阶段操作，每次只处理一个等待项。
5. 若出现 `int` 或 `duration`，继续确认对应阶段；若提示主机确认症状，去“理智与疯狂 → 主机：资源更正、游戏时间与恢复”，选择该角色及“确认症状并掷发作持续时间”，填写症状与依据后确认。是否进入这些阶段由真实损失决定。

本批准效果是 **成功损失1，失败损失1d6**；记录真实 SAN 骰、损失和角色最终 SAN。SAN 卡不应提供幸运或孤注选项。所有必要阶段完成后，才继续最终叙事。若模型叙事回退为确定文本，照实记录，不把它算成模型生成成功。

最后再提交：

> 我回顾刚才已经看见的 Clicker 外形，没有再次靠近或进行新的观察。

预期不会再次发起 SAN，SAN 现值不变。本配置是 `first_only`，新行动事件本身不构成新遭遇。刷新页面也不应重复扣点。

## 6. 另建房间尝试孤注一掷

按第3节另建 **手测11-B：孤注**，复用同一准备、角色卡及 KP；新房间会有独立资源和遭遇记录。按第4节公开声音并提交同一聆听行动。

当原结果自然失败、且卡片提供“申请一次孤注”时，**先不要花幸运或接受结果**：

1. “额外努力或时间花费”填写：`我进一步靠近声源，屏住呼吸辨认声音，不惜花费更多时间，并承担暴露位置的风险。`
2. 点击 **申请一次孤注**。应停在“等待主机核准资格及更严重的失败后果”，此时还没有孤注骰。
3. 在主机审阅表填写资格依据，例如：`原聆听失败；靠近声源改变了尝试方式，仍有辨清细节的可能。`
4. 填写明确的失败后果，例如：`声源察觉调查员的位置，调查员暴露行踪，后续躲避会受此事实影响。` “后果处理”选 **增加角色状态**，“状态”填 `暴露行踪`。
5. 点击 **核准，等待玩家确认掷骰**。卡片应先展示批准的失败后果；点击 **确认后果，掷孤注骰** 才产生唯一一次新骰点。

| 真实结果 | 应看到的行为 |
| --- | --- |
| 孤注成功 | 保留原失败与孤注骰，以孤注结果最终裁决；不增加失败状态。 |
| 孤注失败 | 保留两个结果，服务端增加批准的 `暴露行踪` 状态，再继续最终叙事。 |
| 任一结果 | 不再提供花幸运或再次孤注的选项；刷新不产生第二次孤注骰。 |

可以在“待主机核准”和“已核准待掷”各存一档，按第4节重启方法恢复，检查申请、批准后果和原骰仍在。

另两个分支按需要测试，不必靠反复掷骰凑齐：

- **拒绝申请**：在另一份符合资格的申请上填写拒绝依据，点击“拒绝并接受原失败”。应保留原失败，没有新骰或失败后果。
- **主机手动后果**：核准时选“等待主机处理（伤害、装备等）”并写明后果。若孤注失败，应停在“后果尚未处理”，可存档重启；主机实际处理后填写“实际处理结果”，点击“记录已处理并完成结算”才继续。该选择本身不会自动计算伤害或扣 HP。

若原骰成功或大失败、不提供孤注，记录“未自然出现合法孤注分支”。同一检定不能先花幸运再孤注，也不能靠重新提交同一目标、换技能或清除历史获得额外尝试。

如果还要检查远程真人权限和 PUBLIC 导出：另建一个房间，在另一个独立浏览器会话中用邀请码加入并领取角色。玩家在自己的会话里掷骰、选择幸运／孤注；主机负责准备与孤注审阅。玩家导出的日志才是该玩家的权限视图，且不应出现主机隐藏资料。

本手测使用现成的 `action_target` 自动遭遇。模型省略 SAN、调查揭示后的 `entity_revealed` 自动触发、严格幂等与越权边界，以及未自然出现的随机分支，可另运行第十一批 Fake 用例补充：

```powershell
backend/.venv/Scripts/python.exe -m pytest backend/tests/test_batch11.py -q
```

这些 Fake 用例不等于你刚才的真人会话结果。历史完整验收与规则页码分别见 [第十一批报告](batch-11-report.md) 和 [规则与接口](check-settlement-and-encounters.md)。

## 8. 常见卡点与收尾

| 现象 | 核对方式 |
| --- | --- |
| 5173 首页返回 HTTP 404 | 在前端终端按 `Ctrl+C`，从仓库根目录运行 `npm.cmd --prefix frontend run dev`。本机 `npm.ps1` 会丢失 `--host`，使原命令变成 `vite 127.0.0.1`；后端无需重启。 |
| 主机密钥不正确 | 确认后端由本指南的 `--serve` 启动，并使用测试密钥；旧标签页可换到独立窗口重新解锁。 |
| 无法开始／行动按钮灰色 | 检查角色已分配、席位已准备、准备版本与 KP 已绑定；运行中选择本地真人行动席位。等待中的旧回合须先处理。 |
| 幸运选项没有出现 | 检查可选规则是在掷骰前开启、操作者有权控制该席位、检定仍未最终裁决，并符合骰点及检定种类限制。 |
| 普通聆听卡没有出现 | 检查准备是指定 v8、声音已公开且行动使用完整标题；查看 HOST_DEBUG 中的行动裁决及模型提案。记录实际偏差，不把通用掷骰当作替代。 |
| Clicker 没有自动 SAN | 检查使用新房间、Clicker 已公开、实际观察行动已提交且通过行动裁决；不要在回顾或规则提问中期待 SAN。保存调试记录，不手动补发掩盖问题。 |
| 载入后按钮灰色 | 载入后房间保持暂停，需要点击“恢复游戏”。 |
| 看到了旧公开信息 | 已经公开给玩家的事实不会因读档撤回；资源和等待阶段会回退。这是当前恢复语义。测试首次遭遇优先用新房间。 |
| 模型长时间未返回 | 查看终端 A 与 HOST_DEBUG 中的超时／失败；失败后可用“重试 Agent 回合”恢复同一回合，不重复提交普通行动。 |

完成后分别在终端 A、B 按 `Ctrl+C` 停止服务，保留手测目录便于复查。要下次继续，启动同一目录、打开同一房间即可；不要点击“结束游戏”来代替暂停，因为结束后的房间永久只读。
