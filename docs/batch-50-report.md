## 实现

仅“KP＋当前有效实际结果＋无来源需求”启用 `kp-answer-parts-v1`。模型每个冻结需求只生成 `answer_parts[].text`；唯一来源及无来源 unknown 状态由服务端绑定，多合法来源仍要求受限显式选择。旧的完整 `public_narration`、`body_quote`、`source_quote` 不再由模型各写一份。普通观察、NPC、纯回忆及已知结果模式继续走原契约。

统一 `project_answer_parts` 验证各项、按冻结顺序以双换行组合实际正文，并从同一正文与所选原来源派生旧格式 `answer_coverage`。`restore_output` 后仍是原 `KeeperNarration` 存储／API格式；契约版本、冻结顺序、模型原始JSON文本、派生正文和服务器审计分别记录。没有从第49批旧 coverage 拼出成功正文，没有固定“尚未确认”pattern。

缺项、重复需求或JSON键、错对象／来源、动作无结果、遗漏具体未知项、无来源肯否、跨段矛盾及否定后再说未知均拒绝；沿用原文、数量、条件、归属、当前回执和HO验证。自然未知句允许跨逗号关联其明确对象。长来源只选择同一源中通过事实检查的连续引用片段，完整源仍在审计与语义验证中，不通过截断删除条件。

仍只有一次修复调用。第一稿独立通过语义、权限及回执检查的片段保留，修复schema仅包含剩余项；合并后重新验证所有需求。修复失败按同一投影保留首次有效片段，仍为真实 fallback／`answer_complete=false`。新契约失败调用标为 rejected，旧模式原有逐调用标签保留。

`answer_parts` 专用增量解析在完整对象闭合后立即验证，不等待整个JSON结束；乱序先缓冲，按冻结顺序发布。每项真实来源与需求进入局部校验，累计正文再次校验，未来未知项还未出现时也阻止已出现片段抢先断言其肯否。终态用同一严格JSON解码，避免流式拒绝重复键、终态却取最后值通过。保留 stream／attempt 版本及快照，终稿检查已展示前缀；该模式不再由旧发布分支前插复合检定文字或追加另一份结果正文。

任务结算没有单独改状态。临时流和片段不结清请求，正式正文验证并发布后才由现有原请求key／执行者／目标／回执结算。真实揭示和search结果独立保留；答复“结构未知”不产生“不存在夹层”的事实。
