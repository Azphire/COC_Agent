## 实现范围

`memory/segments.py`与原摘要恢复服务复用`AgentMemory`，以`summary_segment`保存独立段落、人物立场、当前未完成事项投影、场景／人物索引、来源范围、精确必保留记录及覆盖进度；原`summary`保留兼容视图。无需新数据库服务或迁移已有表。全公开输入可形成公开段，含私有输入或目标的段继续按原读者权限保存。召回再次核对有效分支、来源hash与可见性。

重整从原事件和事实读取，不递归摘要旧摘要。普通自动压缩保留最近完整事件窗口，在既有阈值或已结束场景触发；每回合仍至多一次摘要机会，失败不阻塞正常KP。超长单事件按连续原始JSON子块处理，保留offset、长度、hash及此前连续覆盖证明，最后一块到达不单独构成已完整处理的证明。无活动回合时的手动重建可处理已结算历史，最近原对话仍可独立送入行动上下文。

压缩必保留集合由代码投影：精确原payload及`fact_records`派生字段，包含来源、角色、场景、时间、权限、数值、归属、成功／失败及证词／意图属性。模型遗漏时直接补入结构化段文档；保存前比较内容和值，不能仅靠引用ID通过。段、索引、旧版本状态及恢复游标同事务提交。读档revision和运行状态让迟到的生成作废；旧存档缺少段版本时从该分支原事件重建。覆盖率指指定记录已处理且可回查，**不代表自然语言摘要语义无损**。

`memory/recall.py`沿用原事实、结果、库存及`BehaviorState`，按行动、人物、地点、物品与待办召回原文和相关段，普通行动也能得到早期信息。待办保留空间；长原文按有明确offset的来源片段回查。完整来源清单和未装入项留服务端，Prompt只带选中短引用、来源场景／回合与缺证据提示。KP通过公开`response_brief.historical_memory`接收冻结的同一选择，规划和队友接收各自可见内容。历史资料不作为本轮执行回执，公开历史引文仍经过原私密、结果与流式检查。

任务继续用现有引擎：检定成功本身不能关闭交接等操作待办；只有实际操作回执覆盖对应请求才完成。失败或未执行保留未完成操作；取消、拒绝和替代不压成已执行。模型的`goal_status=complete`不能独自清掉尚未结算目标。自由对话承诺只作为带原文来源的候选，不新增执行状态或逐轮抽取模型调用。

## 预算变化

`models/budget.py`统一provider实际封装，与发送相同的system/messages/schema/tools及输出预留一起计量。可用已缓存匹配tokenizer时计token；否则明确标为`conservative_estimate`，按usage向上校准并记录估算误差。字符上限继续单独约束上下文；整条卸载可选材料并记录遗漏，不切断密码、原文或关键数值。必要资料仍放不下则明确失败，不静默截断。

schema去掉展示标题、default注释和不可达定义，将重复约束抽取为等价引用；验证约束不放宽。计入完整schema、system、必要状态及输出预留后，部分规划请求超过旧默认8192的**保守估算预算**，精简后的样例仍估算9412 tokens。因此默认容量改为16384，Ollama继续将该配置传给`num_ctx`；显式8192仍严格检查。既有`.env`及本机配置未改，明确指定小容量的安装不会被静默放宽。后面的实际usage明显低于估算，不能据估算断言本机8k必然容纳不下；提高默认值用于保守预留，也会提高Ollama的上下文分配。没有可用tokenizer时的估算不冒称实际token数。
