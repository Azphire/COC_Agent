## 逐项规则及计算

| 条款 | 原文依据及实现 |
| --- | --- |
| 资格 | 手册PDF35：经学术研究或实际经历拥有神话知识，与KP讨论如何取得并写入背景。读书来源选择相信者或不信者；本包实际经历方案选相信者。不额外设职业或年龄门槛。 |
| 互斥 | 同页包总则：可选，KP同意，五种经历包最多选一个。 |
| 初始神话M | KP允许的数值，1D10+5只是推荐。可手定0–99（软件技能数值范围），也可明确选择建议骰；不把6–15或10当手定上限，不强制随机。三种普通点池均禁购神话。 |
| 最大SAN | 规则书PDF51、131、151：99减当前神话。创建阶段为99−M。 |
| 相信者初始SAN | 手册PDF35：扣与包神话相等的SAN。调整后POW记作P，计算`min(max(0,P−M),99−M)`，先扣包代价再应用上限。P90、M15得到75／84。 |
| 不信者初始SAN | 规则书PDF151：阅读取得知识而不相信，不等额扣当前SAN，上限仍减少。计算`min(P,99−M)`。P90、M15得到84／84；P50、M7仍为50／92。没有“不信者免疫所有神话”。 |
| 两项背景 | 手册PDF35：与神话经历有关的伤疤／疤痕、恐惧症／躁狂症、遭遇的怪异存在中填写两项；保留类别和内容，拒绝缺失或重复内容。不自动添加疯狂发作或游戏遭遇。 |
| 法术 | 手册PDF35：KP决定相信者是否及可以习得哪些初始法术。允许零法术；本阶段只保存核准的已知记录。不信者游戏期可以学习但不能施放的通则见规则书PDF151，学习／阅读服务后续实现，不用它扩大本包初始法术条款。 |
| 神秘学家职业来源 | 原职业仍占个人特长名额，10为建议，不等额扣SAN。初始神话分别记职业／包来源并求合计。未找到职业来源与神话包叠加规则，当前组合报`unsupported_combination`，不静默叠加；这是软件范围限制，非官方禁止。职业＋合法四种旧包仍沿原行为。 |
| 初始SAN0 | 按第31批建立永久疯狂，自主行动受限。创建代价不计入日累计、不生成遭遇或因疯狂获得神话。 |

## 游戏期转换与一次结算

| 条件 | 结算 |
| --- | --- |
| 普通尸体、酷刑或未声明神话直接证据的效果 | 正常SAN流程，不凭描述、模型结论或`mythos=true`自行转换。原文特别指出尸体和酷刑损失不能使其相信神话。 |
| 获准的神话直接证据 | 先作正常SAN检定与损失；实际遭遇损失至少1点时转换。深潜者0/1D6检定成功、损失0，可继续不信。 |
| 目击明显异界生物或神祇化身 | 批准效果须明确事实类别、依据及视觉条件；即使本次遭遇损失0也转换。仍完成正常SAN检定，不凭零损失结果抹去该明确例外。 |
| 玩家自愿相信 | 规则书PDF151允许随时自愿选择并承受损失。本人认证的明确操作记录意愿；服务端取当前神话值，不能自报SAN金额、目标角色或状态布尔。与当前检定串行，不允许绕过SAN0或疯狂发作的自主限制。 |
| 转换基数与顺序 | 当前神话`C=min(99,冻结初始各来源合计＋合法运行期增量)`，取本次新疯狂增长之前的C。本次创伤总量`本次遭遇损失＋C`一起扣减、最低0，实际扣减计日累计并一次判断疯狂。原文欧内斯特例子是神话4＋遭遇2＝损失6。 |
| INT与疯狂 | 合并损失≥5进入原INT流程；累计达到日初SAN的1/5进入原不定疯狂；SAN0永久疯狂。合法神话疯狂的首次5／后续1增量在判断之后走原SAN服务，不再回补进本次转换基数。 |
| 疯狂发作保护 | 原规则书PDF132规定发作中不再损失SAN；现有`bout/awaiting_symptom`保护优先，并保留独立`insanity_bout`回执。保护中的遭遇不产生新的转换损失；不自造结束发作后的补扣。四包免疫仍按原独立原因分类，与不信者状态无关。 |

`SanityEffect.mythos_evidence`只有`direct / otherworldly / deity_avatar`，须`mythos=true`及具体`mythos_evidence_basis`，后两项还须视觉条件；不能兼标普通人类恐怖的排他免疫类别。它来自准备与批准的实体快照，沿现有行动意图、实际目标、揭示事实和遭遇服务核验。旧效果默认空；本批未修改正式批准包，无逐次普通行动的新审批。

冻结卡保存初始相信者状态；`sanity.belief`及`belief_conversion`保存当前状态和一次性凭据，包括检定ID、源事件、实体／效果ID、事实依据、转换前神话、原遭遇损失及游戏日。转换与扣减在原房间锁和数据库事务内完成，原检定及SAN固定骰账本负责重复请求和断点恢复；恢复较早快照则在该时间线重算一次，复用原骰。恢复已完成的相同存档不追加扣减。旧卡缺字段保持`None`，不自动给予不信者收益。

## 创建、法术与许可边界

`experience.mythos`保存知识途径、相信者选择、手定／建议骰方案、两项背景和法术候选。服务端独立生成`initial_mythos_sources`、合计、SAN、初始状态和`known_spells`；PATCH不能上传这些计算结果。职业初始来源每次重建后，包来源只加入一次。

神话骰保存在`experience_rolls.mythos`，用途为`initial_mythos`。只有选择建议骰方案的本地草稿才由DiceService掷一次；改名、重算、重试、撤销再选以及手定／随机切换复用该记录。切回手定仍保留旧骰。导入不生成神话骰，也不因取消再选偷偷补掷；校验来源、公式、用途、数值、ID、倍率及内部一致性，属性／幸运／教育的既有严格校验继续生效。

法术候选有UUID、名称、文献来源和取得方式`experience_mythos`；名称规范化及ID去重。KP逐项查看内容后核准当前包，`known_spells`才形成携带许可的记录，`casting_status=unsupported`。删除候选、改来源／名称／数值／相信者状态／背景或相关规则语义都会使许可失效。导入清除外部许可及核准记录，保留候选原ID供本地主机重新审核。普通改名不失效。角色本人及KP在原权限范围查看这些记录；没有法术效果字段、施放按钮或任意HP／MP／SAN写入入口。

沿既有最终确认、玩家预览提交、主机明确接受事务、冻结和存档链。只有`keeper_approval`可待许可提交，数值、背景、组合和点池错误均阻止；接受时再次校验。1.4.0配置在修改前按字节归档，1.0–1.4按原配置运行；旧版伪造新字段不能获得神话包、状态或法术收益。四包旧许可哈希不因新增空字段改变。
