## 实现及其边界

| 部分 | 实际改动 |
|---|---|
| 当前任务 | `TurnFocus` 分开本轮交流、当前动作、建议、条件假设、谈话对象、动作目标、目的与已有障碍。服务端按标点给当前消息建立最多 12 个语句片段，KP 选择片段 ID，服务端恢复原文；同一片段可同时属于交流与动作。语义分类仍由规划完成。人物、动作目标分别选 ID；移动目标从已选批准出口恢复。行动者、原话、可见性、出口权限继续核验。没有当前动作的规划不能执行世界工具。 |
| 检定 | 删除给全部候选注入“隐蔽或模糊／失败无法辨认”的通用理由。候选只携带实际配置及适用范围。KP 必须先给出当前动作和障碍；没有障碍就不创建普通检定。检定的目的、方法、行动者和不确定性从已有规划绑定，规则和揭示条件仍独立核验。 |
| 撤回 | 自然表达由同一次 KP 规划决定 withdraw/replace/independent/defer；服务端保留本人、尚未掷骰、自愿尝试及固定骰账本检查。成功撤回后仍保留同句 NPC／队友交流；撤回结果只存在于对应子回合。 |
| 公开回应 | narrator 实际输入是本轮问题、回应者、获准公开事实、完成结果和待决定事项。人物介绍与见闻区分；未记载见闻有单独回答类别。私有知识和自由生成的 KP 说明不直接传给 narrator。NPC 台词和旁白分开，可省去空旁白。 |
| 真实结果 | 统一旧模组 `clue_id/content` 与公开回应使用的 `entity_id/public_summary`，避免线索已揭示但后续叙述拿不到结果。队友后续使用自己的触发消息与服务端结果。 |
| 生成负担 | 保留完整外部和落库契约；单次生成语法省略服务端已有的 plan/cycle/角色席位/revision/原话等字段。动作及问题改选当前片段 ID，narrator 选择 claim ID；服务端恢复原文和完整引用。NPC ID 由回应者绑定。规划不再携带无关的 KP 说话风格，保留当前人物实际属性技能。 |
| 历史与摘要 | 当前消息单独提供；待处理队列不进入已处理对话。旧台词保留说话人及证词属性，动作提案标为意图，模型旁白和摘要没有事实授权。摘要实际被选入上下文后才去除其覆盖的重复事件。 |
| 调用审计 | 保留串行模型网关和有界局部修复，没有新增逐句多轮审查。记录阶段、调用耗时、token、输入字符数、实际输入消息、格式或叙述修复原因。直接交给队友回答时可省去没有内容的 KP 公开生成。 |

公开校验增加了针对未完成物品交接、替玩家作决定、第三人称 NPC 台词及部分明确见闻断言的字面检查。**这些检查有明确局限，不能判断所有同义表达，更不能把通过校验当成语义真实。** `focus` 和 `obstacle` 的正确理解仍依赖当前小模型；最终会话出现的问题没有被这些结构检查全部解决。
