## 实现范围

| 部分 | 实际改变 |
|---|---|
| 对话入口 | 默认 `dialogue`，不要求类别、技能或目标。行动、发言、问 KP、回复队友使用同一输入框与时间线；人物和线索点击为辅助。向现有 KP 规划调用提供近期对话，不另加分类模型。 |
| 目标与复合输入 | KP 可用上下文解析称呼；公开人名与 ID 做一致性修复，支持唯一简称，重名具体追问。向队友说话的对象与同时执行的检定目标分别处理。复合输入保留待决定说明，但实测中模型仍不总能正确分段。 |
| 检定政策 | 取消风险关键词、原话包含完整标题、`converse/move/observe` 禁止检定和已公开物品整体禁止等门槛。记录目的、方法、技能、难度、不同成败后果；核验实际角色值、当前可见目标、行动者、规则资格及可执行效果。 |
| 重试与关键条件 | 相同目的、延续尝试或相似任务不能通过换词、换技能刷新普通骰或孤注机会。不同用途可重新裁决。关键揭示仍受场景、前提、结果与批准条件限制；替代方法需要 KP 的具体条件判断。任务相似度是辅助防护，不能证明任意自然语言都被正确判为同一次尝试。 |
| 等待与并发 | 复用 cycle/event/interrupt。新对话持久化排队，等待中的父回合暂停，让无依赖对话先处理；依赖原结果的动作在结果确定后重规划。接受补充在先时，旧掷骰及选择请求不能抢先执行。一个房间的状态写入仍使用现有串行锁。 |
| 撤回与结算 | 仅自己的、尚未掷骰的自愿尝试可撤回或替换。既有遭遇、SAN、固定骰及已生效后果不能聊天撤销。孤注改由 KP 判断额外投入并告知后果，玩家确认后才掷；已实现时间／状态后果自动结算。幸运仍由控制者选择，界面优先列出最低有效花费；没有有效待选项时直接续讲。 |
| 公开叙述 | 保留私有 KP 与公开 narrator 隔离。取消整段叙述及 NPC 台词必须等于依据的要求，允许改写和普通细节。NPC 台词与客观发现分别存事件。校验检查可见性、公开引用、实际结果及部分字面矛盾；报告和审计明确注明这些不是语义正确性的证明。一次局部生成修复后可简短回退，普通回退不自动转主机审批。 |
| 队友 | 根据对话和性格选择发言、协助、行动或沉默；直接称呼提高回应优先级。取消同目标一律重复的限制，保留实质复读检查。`act/assist` 创建自己的 KP 后续回合，不能直接宣布成功；不递归唤起队友。每条真人输入最多一次自发队友介入。服务端拒绝队友直接改变全队场景，即使其提案把移动标成观察。 |
| 恢复与界面 | 存档包含排队对话、暂停父回合、待裁决行动及队友后续。人物席位和主机设置折叠，时间线靠近输入，线索板保留，内部节点、cycle ID 和审批调试放进主机详情。 |

明确的场外规则声明另有服务端只读保护，即使模型把“我问的是规则”误标成世界行动，也不能据此检定或改变世界。自由表述的场外语义仍依赖 KP 规划，实测中的误判已保留。

### 实际对话节选

以下保留实际错误，不是润色后的展示稿。

1. 周岚：“林先生，先别着急。钟停下来前，你最后听见的声音和平常有什么不同吗？”

   KP／NPC 给出了钟声变轻、仿佛被压住的描述。模组未记载这段见闻，应记为编造见闻的问题。

2. 周岚：“我是在问他当时听见了什么，不是自己现在听。先不掷了，我想让他接着说。”

   实际被排队，没有正确撤回。后来明确说“我撤回这次尝试，不掷了”，KP：“好，这次尚未掷骰的尝试已撤回。你可以继续说话或换个做法。”

3. 沈砚：“沈砚接过手电，借着光检查公告背面，同时留意四周是否有异常痕迹。”

   实际公开发现：“公告背面画着从维修间到齿轮平台的路线，旁注‘先查交接簿’。”后续 KP 却说了撤回尝试的旧句，状态正确、叙述错误。

4. 周岚：“那张公告正面到底写了什么？我先把被吹起来的角压平，凑近读一遍。”

   KP 请求侦查，实际骰点 **73 / 技能 60，失败**。玩家接受原结果，没有改点或重置房间。

5. 周岚：“小禾，你先去避雨吧，手电等会儿还你。沈砚，咱们先沿着这条路进维修间。”

   NPC 实际说出了“这雨……好像不是自然下的”，并伴随替玩家决定下一步的叙述。这两项均不应作为模组事实或玩家决定，列入体验缺陷。

6. 存档重启后，周岚：“小禾，我们回来了。手电还在我手里，你要先拿回去吗？”

   NPC：“许小禾接过手电，微微一笑：‘谢谢，我正想去找你们。’”能够续聊，但仍是第三人称台词，而且把询问直接写成递交完成，未达到本批目标。

## 验证与旧断言调整

新增 `test_batch12.py` 定向覆盖：无风险关键词的情境检定、真实行动者权限、等待期间对话与方法替换、旧骰操作拒绝、依赖动作恢复、队友行动真实裁决、物品新用途与任务重试限制、换技能不能刷新骰、KP 孤注资格及玩家确认、后果与固定骰、队列存档重启、公开称呼歧义，以及明确场外指令不能产生世界效果。

旧断言按以下原因调整：

- 等待时第二条行动／规则问题原本期待 409；现在期待接受、串行处理并保留原检定。
- “风险引用不在原文”“代词未写完整目标”“同目标队友行动即重复”等断言与新体验冲突，改为权限、真实条件与实际后续检查。
- 检定前原本期待零 KP 消息；现在验证自然检定提示先于 `check.requested`。
- 真人规划替 AI 请求检定原本被允许；现在禁止，AI 通过自己的后续回合行动。
- 第十一批专门测试主机覆核和各等待态恢复的测试，固定其人工覆核窗口；新的 Batch 12 用例另外验证普通 AI KP 孤注自动裁决，避免把手工窗口测试当自动流程证明。
- 导航与主机异常审阅测试夹具改为队友发言，隔离原流程；队友真实动作由 Batch 12 用例覆盖。工具注册安全检查继续保留，不再依赖提示词中完整 JSON 工具表的文本形状。

回归期间另外修复：规则回答结束后原等待项的原子恢复；裁剪上下文时优先去掉重复场景文本并保留提案来源，完整版本与来源哈希仍在检索记录中由服务端核验；不再把 NPC 人物摘要自动转换成其“说过的话”；撤回检查查询固定骰账本，载入掷骰前存档也不会重新获得撤回机会。全量又发现掷骰成功后立即暂停、读档时，旧任务可能覆盖恢复状态；暂停现在取消并等待旧任务退出，且不会把这种主动暂停记为回合失败。回归用固定成功骰及节点屏障强制重现该交错时序，检查固定骰不重复、撤回被拒、后续正常完成。这些后期修复有定向验证，未冒充整段自由互动已经在最终代码上重新通过。
