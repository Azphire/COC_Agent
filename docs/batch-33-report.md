## 实现与交付链

新增`domain/mythos.py`、`rules/mythos.py`、`rooms/mythos.py`三个小模块，接入既有经历、职业重算和SAN服务，没有建设通用效果引擎。

- **来源和重算**：职业来源先按原逻辑重建，随后仅合入一次包来源，服务端生成`initial_mythos_sources`、合计、各来源批准状态与SAN代价。技能、实际检定、KP上下文及本人查看使用初始合计＋合法运行期增量。三种普通点池均不能购买神话。
- **原骰**：明确选择建议骰才由DiceService产生一次`experience_mythos / initial_mythos / 1d10+5`记录。改名、重算、重试、撤销重选、手定与随机互换复用原记录；手定时仍保留旧骰。导入不补掷，并验证公式、用途、来源、骰数、总值、倍率和跨来源ID唯一性；属性／幸运／教育的原验证不放宽。
- **许可和法术**：候选保存稳定UUID、名称、文献来源及取得方式；同名／同ID拒绝，只有本地核准后才生成携带许可的`known_spells`。收益、状态、背景、法术和相关规则语义变化会使许可失效，普通姓名变化不会。导入清除外部许可与已核准状态，保留候选ID供主机核对。只有`keeper_approval`可待许可提交，其余非法值、组合和点数不能靠勾选绕过。
- **UI与权限**：车卡表单、摘要、最终确认、JSON、玩家预览、主机接受、冻结卡和运行卡一致展示来源、两项背景、相信者选择、SAN前后值、法术候选／核准状态。角色本人和KP沿原可见范围查看；UI写明“尚不支持施放”，没有施法按钮或任意HP／MP／SAN效果入口。

冻结保存初始状态；当前`sanity.belief`和`belief_conversion`在运行时保存。仅有经本地许可且版本支持的神话包启用转换，旧卡缺字段保持原行为，不自动成为不信者。

批准SAN效果可声明直接证据、明显异界生物或神祇化身及具体依据；后两类须视觉条件。它随准备与批准实体快照进入现有正常行动链，核对实际揭示和目标，不根据模型一句“相信了”或客户端布尔值修改状态，也不为每次普通行动新增审批。原正式批准包保持原值。

| 游戏期条件 | 实际SAN服务行为 |
| --- | --- |
| 普通尸体／酷刑、无神话证据、目标或揭示条件不匹配 | 不转换；依原效果正常处理 |
| 直接神话证据，普通检定损失0 | 可继续不信，不默认免疫其他神话损失 |
| 直接神话证据且本次损失≥1 | 转换，追加当前神话值 |
| 明显异界生物／神祇化身的获准目击 | 本次损失0也转换 |
| 玩家自愿相信 | 本人认证、明确意愿、房间版本及自主资格检查；服务端取当前神话，沿同一结算服务处理，不让客户端报损失金额 |
| 疯狂发作／等待症状 | 原保护优先，继续保留独立`insanity_bout`回执；不产生新的转换损失，不自造保护结束后的补扣 |

转换取新疯狂增长**之前**的当前神话C，和本次遭遇损失合并扣减，实际扣减只计一次日累计，再判断INT／疯狂／SAN0。已核对原文神话4＋本次2＝6的例子；测试另覆盖初始7＋合法运行增量5＝当前12，转换12＋本次2＝14，之后合法疯狂再增1，正常检定与KP上下文均读13。不会把后增的1回补到转换费用。

转换凭据包含检定、源事件、实体／效果、事实依据、转换前神话、遭遇损失、游戏日和时间。扣减与凭据沿原房间锁及事务完成；重复请求、SAN与损失之间恢复、相同存档反复载入均不重复结算。SAN0继续限制普通、物品、AI和战斗自主行动。
