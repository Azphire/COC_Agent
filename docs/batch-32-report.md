## 服务端、交付与运行时

`rules/experiences.py`是独立小模块，规则配置提供资格、点池、白名单、SAN骰式与精确免疫范围。角色以`experience`保存方案／背景，`experience_skills`记录第三点池；原职业／兴趣账本不混用。失效经历投入保留并明确报错，可在UI退回经历池。最终技能值、余额、SAN及效果由服务端重算，PATCH拒绝客户端上传计算结果、原骰或许可映射。三个点池合计仍受技能上限约束。

`experience_rolls`与原属性／幸运／教育`roll_records`分开，采用新增用途`experience_san`；`expected_rolls()`的原校验没有放宽。每包第一次选择由现有DiceService产生一次，之后修改普通资料、改同包身份、撤销再选、重复保存全部复用该包记录。导入保留ID、时间、原值和公式，来源标为imported，校验用途、包键、公式、倍率、骰子范围、合计及ID一致性；缺少原骰不在导入或普通修改中偷偷补掷。外部自带的内部一致记录仍需本地主机核对。

`experience_approvals`独立于职业两项特例。许可绑定实际规则ID／版本／模板、包方案、年龄与属性原骰、职业选择、专业、三池投入和职业特例；这些内容改变后旧许可失效，改姓名保持许可。导入清除外部许可。沿既有认证和房间提交事务，仅`keeper_approval`问题可待许可提交，点数／资格错误拒绝。主机看到具体技能收益、SAN代价及背景后勾选核准；接受、确认、发布、冻结和读档均不重扣或重掷。

UI包括四包来源／资格、专业组、独立投入与退点、SAN前后／原骰、分别显示资格错误与待许可原因。车卡预览、最终确认、JSON、玩家提交预览、主机接受及运行期冻结详情共用服务端结果。KP上下文和本人角色查看可读取有效方案与限定效果。

批准的`SanityEffect`增加可空`experience_category`和必需来源说明`experience_basis`，目击类须明确视觉条件。类别指**损失的独立、排他原因**，不能给混合恐怖、复活尸体或怪物仅贴一个“尸体”标签。旧效果默认未分类，继续原逻辑；不匹配关键词，也不把`mythos=false`当作普遍免疫。原正式模组包未改，新类别只在隔离批准夹具使用。

运行时按冻结卡的精确版本和有效本地许可匹配类别。命中则直接完成同一遭遇回执，记录适用包、来源及原因；SAN／损失骰均不掷，SAN、当日损失、神话增量不变。原疯狂发作保护标记`insanity_bout`，新包免疫标记`experience`。权限过滤、自动遭遇、重复请求、保存恢复语义保留，无新增逐遭遇手动许可。未匹配或未分类仍走正常SAN检定和损失。

旧1.3.0卡、导入和冻结房间仍按旧版计算，新字段缺省为空／0；旧版伪造新字段不能取得收益／免疫。第30批职业特例与第31批自主限制保留。
