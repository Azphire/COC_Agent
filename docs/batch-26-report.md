## 免检定发现修复

第 25 批第三次观察已包含示意图候选，但计划只读取资料，随后声称没有图示。第 26 批在实际 `KeeperPlan` 规划入口增加 `automatic_discoveries`：只提供当前场景、尚未揭示、类型为物品／线索／地点、所有揭示前提已满足的免检定候选。候选不直接包含隐藏内容。

规划说明明确区分读取、公开发现和发现隐藏细节。针对已经选择的合法观察目标，在检定归一处理之后补齐揭示提案，仍经过原有行动权限、上下文补充和揭示服务。不会因出现候选直接批量揭示，不授予库存。否定、假设、回顾、拿取以及有待裁定检定的动作不走该补齐路径。

首次本地短测仍失败：模型选中了示意图，但提出了无关隐藏细节／多余检定；服务端拒绝其隐藏揭示，没有形成示意图回执。该次暴露补齐逻辑位于多余检定清理之前，以及提示需放在实际两阶段规划入口的问题。修正后在同一房间保留旧步骤，发送一次新的自然观察；没有替换原请求、回填模型输出或修改批准包。

## 自定义专业规则与兼容

- 角色可选字段 `custom_specializations` 保存 `{id, group, name}`；空列表兼容既有角色。每卡最多 50 项，名称 1–40 字。
- YAML 通过 `custom_specialization_templates` 继承已有基础值、99 上限、年代和可分配标记：外语 1、艺术／手艺 5、科学 1。客户端不能上传基础值、公式或上限；数学仍使用目录内基础 10 的项目。
- 同类别名称按 NFKC、大小写和空白归一比较，目录同名、重复 ID 及非法类别均受校验。已存在的中文目录名直接选用；不声称识别所有语言的同义专业名。
- 自定义项进入原职业分组和兴趣选择，职业名额与点池保持原规则。改名保留 ID 与投入；删除清理选择及分配。API 单独删除定义而留下投入会被拒绝。
- 导入重算并忽略伪造派生数值；已确认卡、房间快照持有完整定义。KP 上下文带自定义 ID 与名称，普通及复合检定显示读取参与角色自己的快照。
- 当前目录版本仍为 **1.1.0、31 职业、103 目录 ID**；自定义项是每卡扩展，不计入共享目录总数。旧 1.0.0 配置未开启模板，不重算已有房间或原骰。

来源沿用 [SOURCES.md](../backend/app/rules/definitions/SOURCES.md) 中第 21 批专业核对。未增加职业、90+、战斗特例或完整法术规则。
