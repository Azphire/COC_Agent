## 修改内容与边界

1. **NPC 对话与时序。** `dialogue.py` 依据已选交谈对象、可说话状态、已批准证词和资源主题，将普通互动作为默认可回答范围；疼痛、听觉、情绪等无需问候白名单或核心线索引用。关键外部事实仍走证据契约。历史物品证据携带各自来源、主体、过去持有和最后位置，黑包掉落不能自动推出钥匙掉落，也不能由过去持有推出当前持有或当前不持有。
2. **按问题保留答案。** 契约暴露 `question_index`；两次生成之间累计有效答案，保留原已通过项，只补失败项。修正资料投影为第一人称；未知回答必须确实表达认识上的不确定，不能用一个“不/没”掩盖无依据断言。全部生成失败与 NPC 真不知情分开：已知内容保留，生成缺口由 KP 明示。拒绝原样回声式“回答”。
3. **任务适用性。** 进入队友调度前统一整理新要求与旧待办：完成、替代、取消、不可接触归档到现有状态的 `request_history`；新要求先响应。转场不一律丢弃任务，携带物和持续目标保留；远处物理目标暂不可执行。每项请求保留技术失败状态，实际检定失败记为 blocked，不因发了新问题而重新当作技术失败刷骰。
4. **经历与结果记忆。** 有界公共记忆保留说话人、本人/他人、尝试/判断/证词/结算及更正状态；新回执或证词使相关旧说法成为历史投影，原事件不删除。`last_attempt_result` 单独保存本人实际结果，后续闲聊不会覆盖它。补充冒认他人动作、无依据引语、旧物品持有说法和未执行医疗承诺的校验；这些校验仍非完整语义事实验证，正式局发现的漏判见下文。
5. **具体动作与优先级。** 结合职业技能、当前证词、风险、未完成请求选择现有主动机会；区分结果追问和新任务，去掉会吞掉有效动作的重复附带台词。没有要求每轮全员发言。处理已经选中 NPC 但问题标签误放进动作的现场；明确当前移动不再被旧 SAN 澄清覆盖。保留第36/37批移动、方向、治疗、通道顺序和原骰恢复机制。
6. **运行与审计。** 复用第36/37批驱动和审计，仅增加批次隔离、8038 端口、原骰恢复核验、逐场景版本记录和父子周期耗时并集。原始数据库、检查点、认证文件仅供本机恢复；可交付范围是脱敏导出。

## 审计口径

模型调用失败按 `error_category` 逐调用统计，包含后来修正成功的调用；队友最终决策失败另计，并排除因无触发条件而确定性跳过。完整/局部回退按周期和 `validated_partial` 区分，不能仅数公开 `safe_fallback` 标签或把两种回退混为一谈。无效澄清需人工核对原句与公开事件。

模型耗时来自实际调用记录。应用/等待耗时使用所有已完成周期的时间区间**并集**减模型耗时，避免父子周期重叠重复累计；它包含校验、队列、检查点及等骰，并非应用 CPU 耗时。完整会话的墙钟时间还包含玩家读日志和本批整理报告时间，不能冒充模型延迟。

所有目录的旧事件、坏台词、失败、原骰和修正记录都保留。`acceptance-20260918-final` 虽然名字含 final，实为中途修改过应用代码的调试局，已在 `debug-status.json` 明确标记，不能并入正式新局的通过数或结局证明。
