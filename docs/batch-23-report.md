## 1. 配置与模型入口

- `Settings` 保存环境凭据的原始值及来源，避免 UI 配置覆盖后丢失回退信息；进程环境优先于根 `.env`。
- 集中解析顺序：**同一服务显式保存的密钥 → 为原服务配置的有效 MODEL_API_KEY → 官方服务的 OPENAI_API_KEY**。空串、大小写及空白包围的 `ollama` 占位值不挡住回退。
- 官方回退仅接受 HTTPS、`api.openai.com`、443 端口、`/v1/` 路径；规范化大小写、默认端口及末尾斜杠。不同主机、端口、路径或协议不会继承原平台密钥；适配器禁止重定向。
- 环境密钥保存为空值加来源，重启可读取更新后的环境值；显式保存密钥仍遵循现有本地配置机制。新增密钥不会改变用户原 provider/model。本批官方 API 选择仅保存在隔离设置中。
- 设置状态、`ready()`、模型工厂和 API 适配器共用解析器；UI 始终不回填密钥。实际浏览器截图为 `settings-verified.png`。
- 档案、模组准备、游戏运行时和摘要共用 `AgentModelClient`；新增集成测试实际切换后调用档案／准备／摘要入口，使用 fake adapter 核对网关重建、来源和状态不变。这些是确定性验证，不计作付费 API 调用。

沿用 Chat Completions，请求 `gpt-4.1-mini`，真实响应模型均为 **`gpt-4.1-mini-2025-04-14`**，输出模式 `json_object`。选择参考[官方模型文档](https://developers.openai.com/api/docs/models/gpt-4.1-mini)，账户可访问性由本次实际响应确认。根 `.env` 的读取由应用负责，显式向 SDK 传入集中解析后的密钥，参见[官方快速入门](https://developers.openai.com/api/docs/quickstart)。

`json_object` 后仍执行完整游戏 schema、语义和权限校验。`json_schema` 对 `PlannedTool.arguments` 等开放字典继续明确拒绝；没有删除游戏参数来满足严格模式，也没有实测宣称完整游戏严格模式可用。[官方结构化输出规则](https://developers.openai.com/api/docs/guides/structured-outputs)

调用记录新增脱敏 `request_id`、`response_model`、`error_category`，保留耗时、attempt、schema 和返回 usage。SDK 自动重试为 0，既有格式修复最多一次，每次请求占原预算；认证、额度、网络错误不自动换模型或重试。拒绝、截断、格式失败及网络错误用 mock 定向验证，没有刻意制造付费错误。

## 2. 真实短测、失败与修复

原创《停摆的钟楼》，房间 `80080d70-9875-4099-8459-782b72cafa3b`，玩家周衡、KP、AI 队友沈岚。两张卡通过正常购点、装备、完成及房间分配接口创建，各有一把真实小刀，不依赖历史音乐家导出文件。

| 实际阻断 | 修复及复验 |
| --- | --- |
| 队友规划及物品请求超出既有 6092 字符规划视图预算 | 压缩重复的绑定／角色路由信息；具体实例转移只省略无关发现菜单与检定数值，保留库存、交互条件、原始动作和完整审计上下文。不扩大上下文预算 |
| KP 只描述“时间紧迫／受伤风险”，空调查计划被接受 | 风险描述进入既有有限计划修复，由 KP 继续决定目标及检定；实际无法接近仍可说明障碍，不由执行层选骰或宣布成功 |
| 两人同名“小刀”使“自己持有”放下被误判歧义，后续又错绑场景而无操作 | 冻结裁定前用实际持有实例或原话中的唯一实例编号消歧；同名但无法确定仍要求澄清。真实放下／拾回和武器投影已复验 |
| 重复拾取后带“如果已经持有”使压缩漏判 | 按独立动作分句识别具体转移；重复请求恢复后仅报告现状，没有第三个交互回执 |
