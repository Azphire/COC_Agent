# 规则提问、公开事实范围与剧情摘要

输入区选择“调查行动”或“规则提问”。调查员询问 NPC 世界内的规矩仍选择调查行动。规则提问不会要求角色说明行动目标，也不会选择 NPC、生成 KeeperPlan、掷骰、公开实体、转场、调用队友或自动更新游戏摘要。房间必须运行且已启用 Agent；有活动回合时继续等待。

## 接口

沿用 `POST /api/rooms/{room_id}/actions` 和原有房间身份令牌：

```json
{
  "text": "奖励骰和惩罚骰怎么使用？",
  "category": "rule_question",
  "client_request_id": "唯一 UUID"
}
```

`category` 可为 `investigation`（默认，兼容旧客户端）或 `rule_question`。主机代本地真人席位操作仍使用 `actor_member_id`；远程玩家只能操作自身身份。规则提问不接收 `target_entity_id` 或 `clarification_event_seq`。不同正文、类别、席位、目标或澄清对象必须使用不同请求 ID；相同请求重试返回同一提交事件，不重复答复。前端按完整请求内容维护幂等键。

规则提问仍建立轻量 cycle，复用房间调度与恢复状态；直接执行 `answer_rule_question`，不进入行动图。日志保留 `rules.question` 和 `rules.answered`，时间线显示“规则问答”。答复载荷包括 `question_seq`、`cycle_id`、`text`、`answers` 和 `citations`。每项 answer 有原问题、正文、`evidence_ids` 和状态：

| 状态 | 含义 |
| --- | --- |
| `topic_reference` | 当前绑定的精确来源版本命中已经核对的主题，返回完整主题释义 |
| `related_excerpt` | 走现有规则 RAG，仅返回本次检索原文，明确不保证覆盖所有细节 |
| `not_found` | 未找到对应公开规则依据 |

独立子问题分别处理；复杂或未完整覆盖的问句不会仅因包含已知术语就跳过 RAG。规则答复使用确定性组织与摘录，不新增生成模型调用。答复 run 的上下文仅含问题及当次公开规则证据，不含模组正文、角色私密信息、摘要或行动工具。引用保留来源、edition、版本 hash、实际页码；已核对主题另保留来源版本号及多页列表。解释未实现的规则不会开放游戏状态操作。

原 JSONL／Markdown 日志导出保留问答。主机仍通过 `GET /api/rooms/{room_id}/agent-runs/{run_id}/retrievals` 检查查询、来源过滤、structured／rag 路由及实际使用证据；玩家不可读取该审计接口。

## 公开事实范围

`game.public_entities` 与 `/public-entities` 增加 `fact_scope` 和 `scope_label`：

| fact_scope | 展示 | 含义 |
| --- | --- | --- |
| `current_scene` | 当前场景 | 当前批准绑定内且已经公开 |
| `historical` | 先前获知 | 先前实际场景中的公开知识；当前位置未确认 |
| `unknown` | 位置未确认 | 没有充分的位置依据 |

服务端按实体 ID、批准 ModuleIR 绑定、当前导航及实际公开转场记录派生范围。同名不等于同一实体；多场景绑定可以在多个实际场景适用。公开范围不输出隐藏／未来绑定的名称或 node ID，也不推断物品随身、NPC 自动跟随或实体已移动。结构缺失或无效时保留公开知识，保守标注位置未确认。

调查板保留全部历史知识。KP 和队友使用相同投影，再按本轮问题选择相关内容。叙事优先本轮目标、实际公开结果与当前场景；相关历史摘录必须带“先前获知（当前位置未确认）”或“已知信息（位置未确认）”。发布时再次验证范围；先前 NPC 不能在新场景回答。`recall` 是只读行动意图，只能回顾实际公开的信息，不执行角色工具或检定；叙事失败时仍可返回经验证的历史摘录。

存档恢复当前位置。沿用仓库已有的公开知识单调保留规则：玩家已经收到的发现／修正不撤回，恢复到旧存档后仍作为已知历史保留，不视为再次发现。

对“我回顾／回想／复述……”且没有新行动的明确输入，服务端可将模型误判的意图校正为只读 `recall`，保留原模型输出及 `intent_normalization` 审计。显式已公开目标或唯一同名匹配确定回顾对象；多个同名对象且未指定 ID 时仍由原裁决处理。带移动、交谈、使用或检定等行动的句子不会被这条规则改写。指定旧线索时，候选及回退都过滤无关历史信息。

## 剧情摘要与恢复

`story_v1` 共用选择器用于自动摘要阈值、摘要输入、近期上下文、pending 恢复及手动重建。先按身份过滤事件，再选择剧情，最后决定窗口和预算。保留真人行动、明确聊天事件、KP／NPC／队友有效输出、实际检定、公开／修正和转场；排除初始化、房间成员管理、角色发布／分配、知识绑定、检索审计、规则问答和后台运行通知。原日志不删除。

`snapshot.loaded` 使近期剧情输入回到存档的剧情分支；原始公开知识仍由事实投影保留。摘要 coverage 使用真实 seq，seq 间隔可能包含被排除记录。`source_event_ids` 列出实际摘要事件；预算只处理最早未处理剧情的连续前缀，不跳过超大事件。首个事件装不下也记录 stale／pending 和失败次数，不调用模型，不越过它。

`current_participants.members` 为当前活动成员映射，`assignments` 仅为真实成员到已分配角色的映射。未分配的已发布角色不会成为已分配角色；自然语言旧摘要不能覆盖这份当前状态。旧 JSON／表结构继续使用，未新增数据库列。

每轮最多一次自动摘要尝试，保留旧摘要、失败退避、自动恢复停止与主机手动重建。主机 cycle 的 `summary_selection` 记录候选、排除原因、未摘要数、实际选中 seq 和 coverage 口径。摘要阈值未提高。现有摘要仍属于模型生成的简短回顾，不提供全面语义正确性评审。
